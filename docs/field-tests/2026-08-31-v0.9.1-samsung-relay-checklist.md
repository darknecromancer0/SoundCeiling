# SoundCeiling v0.9.1 Samsung Accessibility Relay checklist

Целевое устройство первого прогона: Samsung SM-A528B / Android 14. Это экспериментальный
field-build для проверки одного no-root audible-пути на встроенном динамике, а не разрешение к
публикации в магазине.

## Немедленные стоп-условия

**Сразу остановить SoundCeiling, больше не повторять тест и экспортировать полный лог**, если
появились эхо/дублирование, резкий громкий импульс, сломанный звук, зависание на полной громкости,
игнорирование Volume Down, либо Samsung Media не восстановился после Stop/abort/process death.
Не переносить неудачный тест на наушники, Bluetooth или внешний динамик.

## 0. Install-over, APK и исходные ограничения

- [ ] **Install-over from v0.9.0** выполнен без очистки данных; Android показывает v0.9.1
      (`versionCode 37`).
- [ ] Записаны commit, GitHub Actions run и SHA-256 APK.
- [ ] `apksigner verify --print-certs` показывает development signer SHA-256
      `5AA109027B8AE7675CE543EAF26402A2890BCA97510BC2018661EA2231516BE2`.
- [ ] Включён только встроенный динамик; Bluetooth, USB, проводные наушники и cast отключены.
- [ ] Разрешён ровно один источник: Yandex Music **или** YouTube. Второй плеер, системные звуки и
      другие MEDIA endpoints остановлены.
- [ ] Enhanced Session DSP по-прежнему показывает
      `field_quarantined_neutral_media_bypass`; PCM Shadow остаётся `SHADOW_ONLY` и неслышимым.
- [ ] До Relay Samsung Media вручную установлен на тихий безопасный шаг, а Safety Maximum — на
      заранее записанный низкий предел.

## 1. Свежий consent и Accessibility connection

- [ ] Остановить обычный precise engine, затем нажать `Запустить Relay-тест`.
- [ ] Прочитать весь disclosure: PCM остаётся локальным, original Samsung Media временно станет
      нулём, audible output пойдёт через Accessibility, поддерживается только встроенный динамик.
- [ ] Выдать новый MediaProjection consent; не использовать старый/stale projection.
- [ ] В Android Accessibility включить `SoundCeiling Strict Safety` и убедиться, что управление
      accessibility volume действительно доступно.
- [ ] В логе `strict_safety_accessibility` указано `capability=true`; при недоступной фильтрации
      аппаратных клавиш Relay обязан отказать с `relay_accessibility_key_filter_unavailable`.
- [ ] Если подключён spoken screen reader или другой конфликтующий Accessibility-аудиосервис,
      Relay обязан отказать с `relay_spoken_accessibility_conflict`; не обходить этот отказ.

## 2. Exact source и PRE_VOLUME proof

- [ ] Запустить один разрешённый трек и дождаться exact targeted capture: один UID/package, один
      endpoint, активный playback и завершённый capture warmup.
- [ ] В логе `source_confidence=EXACT`, `metering=PCM_EXACT`; mixed/likely/unknown не принимаются.
- [ ] В логе переход `capture_reference` подтверждает `PRE_VOLUME` до начала mute.
- [ ] Появляется `relay_preflight_passed`; отсутствуют
      `relay_source_not_exact`, `relay_multiple_endpoints`, `relay_prevolume_not_proven` и
      `relay_projection_epoch_stale`.
- [ ] Service/projection/capture/source/route generations не меняются от preflight до Stop. Любая
      смена даёт отдельный fail-closed reason и не переиспользует прежний epoch.
- [ ] Если PRE_VOLUME не доказан, Relay остаётся неслышимым и не двигает Samsung Media.

## 3. Media 0 и продолжение capture

- [ ] Записать Samsung Media непосредственно перед Relay; это значение должно храниться только как
      recovery lease и не становиться обычной целью нормализации.
- [ ] После `relay_media_zero_write` физический Samsung Media подтверждён как **Media 0** событием
      `relay_media_zero_acked`.
- [ ] При Media 0 targeted PCM продолжает приходить и проходит muted-capture proof; лог содержит
      `relay_muted_capture_proven`.
- [ ] До этого доказательства Accessibility renderer не выдаёт audible PCM.
- [ ] Любое ручное изменение Samsung Media во время lease трактуется как пользовательский выход:
      Relay останавливает renderer и не перетирает новый пользовательский выбор восстановлением.

## 4. Пятисекундная тихая проба

- [ ] До старта вручную установить Accessibility volume не ниже показанного probe-шага. Relay не
      имеет права автоматически поднимать его; недостаточный уровень даёт
      `relay_accessibility_probe_level_required` до открытия audible renderer.
- [ ] Состояние UI — `Тихая проба Relay`; длительность не более пяти секунд.
- [ ] Перед первым ненулевым sample muted pre-roll подтверждает непустой точный built-in route, а
      публичный playback-config delta содержит ровно один новый Accessibility/Music renderer.
      Null/ambiguous route или ownership дают `relay_route_changed` либо
      `relay_renderer_topology_unproven` без слышимого выхода.
- [ ] Нет `relay_foreground_playback_type_failed`; если Android не подтверждает обязательный
      `mediaPlayback` foreground type, Relay возвращает Media и не открывает renderer.
- [ ] PCM peak пробы не превышает `-30 dBFS`, Relay Volume-Up до подтверждения заблокирован.
- [ ] Слышен ровно один очень тихий чистый поток без исходного дубликата, задержанного эха,
      дребезга и громкого начала.
- [ ] Если всё чисто, нажать **`Один чистый тихий поток`** только для текущего epoch.
- [ ] При любом сомнении нажать `Эхо / громко / не работает`; состояние должно немедленно уйти из
      probe/confirmation, renderer остановиться раньше восстановления Media.
- [ ] Stale confirmation от предыдущего epoch не активирует Relay.

## 5. Audible leveling: Safe и явный Full

- [ ] В `Safe +3 dB` проиграть не менее 30 секунд тихого, затем громкого участка и участок с
      выраженным пиком, не двигая Samsung Media.
- [ ] Тихий участок даёт положительный `relay_pcm_gain`, но applied gain не выше `+3.00 dB`.
- [ ] Громкий участок уменьшает gain/даёт attenuation; пики не проходят выше конечной границы
      `-6 dBFS`; финальный renderer повторно проверяет PCM16 `abs(sample) <= 16422`, clipped
      samples остаются 0.
- [ ] Сравнить слышимое направление с Shadow telemetry: тихое становится ближе к цели, громкое и
      пики понижаются, без pumping/ступенчатого Samsung Media.
- [ ] Только после успешного Safe-теста вручную выбрать `Full experimental +12 dB` и повторить те
      же три участка на исходно тихом Relay volume.
- [ ] Full никогда не включается до ручного подтверждения пробы и всё равно сохраняет конечный
      peak ceiling, saturating conversion и zero-clipping contract.

## 6. Safety Maximum и попытки превысить cap

- [ ] Поставить loudness target выше **Safety Maximum**. Relay output не становится громче
      рассчитанного accessibility hard maximum, а Samsung Media остаётся 0 в owned lease.
- [ ] Перетащить Relay volume выше hard cap. UI/runtime ограничивает applied index значением
      `relayVolumeHardMaximum`; фактический accessibility index совпадает с подтверждённым readback.
- [ ] В Full режиме повторить target/cap попытку: `+12 dB` — предел алгоритма, а не разрешение
      обойти output peak или Safety Maximum.
- [ ] Ни одно cap-событие не меняет прежний Samsung Media anchor и не создаёт Media debt.

## 7. Аппаратные клавиши и Samsung panel

- [ ] Десять раз чередовать короткие Volume Up/Down. Во время ACTIVE клавиши управляют только Relay
      accessibility volume; Volume Down применяется немедленно, Volume Up не проходит hard cap.
- [ ] Удерживать Volume Up у cap три секунды: нет full-volume lock и повторных скачков.
- [ ] Открыть Samsung Media panel и несколько раз сдвинуть Media с 0. Это должно завершить Relay как
      `relay_user_media_exit`; SoundCeiling не возвращает panel к 0 и не переписывает выбор вверх.
- [ ] После user exit снова запускать Relay можно только с новым preflight/probe epoch.

## 8. Все abort-пути

Для каждого подпункта начинать с отдельного чистого Relay epoch и проверять порядок: renderer stop
→ neutral/cleanup → Media restore либо явный `RECOVERY_REQUIRED`.

- [ ] Нажать `Остановить Relay` во время ACTIVE.
- [ ] Завершить/сменить exact source.
- [ ] Отозвать MediaProjection.
- [ ] Выключить Accessibility service.
- [ ] Переключить маршрут со встроенного динамика на наушники/Bluetooth и обратно.
- [ ] Проверить, что ни один abort не оставляет audible renderer, stale gain или автоматический
      повторный старт; unsupported route остаётся `relay_route_unsupported`.
- [ ] Если mute/pause/flush/stop/release и final uninitialized state не подтверждены вместе,
      появляется `relay_renderer_stop_unconfirmed`: Media остаётся 0, restoration не выполняется,
      состояние остаётся `RECOVERY_REQUIRED`.

## 9. Forced process death и recovery

- [ ] Во время owned Media 0 принудительно завершить процесс приложения.
- [ ] После нового запуска UI явно показывает `RECOVERY_REQUIRED`, а Relay не стартует.
- [ ] Нажать `Восстановить безопасный Media`; восстановление ограничено сохранённым pre-Media и
      captured Safety Maximum и не перетирает более новый пользовательский выбор.
- [ ] Recovery record очищается только после подтверждённого readback; при ошибке остаётся
      `relay_recovery_required` для следующей явной попытки.
- [ ] Install-over корректно распознаёт старую pending recovery-запись без generation tuple: она
      допускает только явное безопасное восстановление, но никогда не возобновляет старый Relay.
- [ ] Повторить обычный Stop после recovery и убедиться, что Samsung Media не восстанавливается
      второй раз.

## 10. 10 минут стабильности, latency и экспорт

- [ ] После всех предыдущих пунктов выполнить **10 минут** непрерывного Safe Relay на одном
      разрешённом источнике и встроенном динамике.
- [ ] В финальном логе есть не менее 20 resolved `relay_renderer_latency` timestamp markers.
- [ ] Первые 20 markers разрешаются не позднее двух секунд; repeated/stale AudioTrack timestamps
      не считаются новым evidence и приводят к `relay_latency_evidence_timeout` либо
      `relay_renderer_timestamp_unavailable`.
- [ ] Итоговая задержка: `median <= 120 ms` и `p95 <= 200 ms`; нет
      `relay_latency_out_of_bounds`, renderer underrun/stall или unexpected playback-head reset.
- [ ] За весь прогон нет Session DSP constructor/attach/apply, audible Shadow output, PCM/log dump,
      clipped samples, неразрешённого route/source либо самопроизвольного Media UP.
- [ ] Экспортировать логическую сессию целиком — от запуска приложения до окончательного Stop — и
      отдельно записать время каждого audible наблюдения, Safe/Full режим, Relay volume, Safety
      Maximum и видимый Samsung Media.

## Критерий прохождения

v0.9.1 считается лишь технически пригодным для следующей полевой итерации, если все пункты зелёные,
а финальный Stop возвращает безопасный Media. Один echo, громкий transient, full-volume lock,
ошибка восстановления или выход latency за пределы отклоняет весь audible Relay-путь; PR #8 после
этого всё равно остаётся draft до разбора полного лога.
