# SoundCeiling v0.7.7.3 Samsung Enhanced Session checklist

Purpose: verify the Samsung constructor compatibility corrective without reintroducing the historical active-limiter attenuation.

## Setup

1. Install the exact v0.7.7.3 debug APK and record its APK SHA-256.
2. Set **Media to 3/15** for the first run.
3. Start Yandex Music playback, then enable SoundCeiling and Enhanced Session DSP/source recognition as required by the existing setup flow.
4. Export the SoundCeiling log after the session has attached or failed closed.

## Required evidence

- Exact non-zero audio session and UID/package ownership are discovered for Yandex Music.
- There is no `dsp_create_failed` at the historical Samsung-compatible constructor step.
- Before any Enhanced Session effect enable, the log/reason path reaches `pre_enable` sanitation; failure here must leave DSP unavailable and audio untouched.
- `session_dsp_readback_result` reports verified only after the sanitized limiter shell has read back disabled and neutral.
- The active readback handshake remains `0 dB -> -0.5 dB -> 0 dB` on every configured channel.
- No immediate ~16 dB volume collapse appears when Enhanced Session DSP attaches.

## Fail-closed checks

A sanitation/readback mismatch must not promote the transport to verified policy-scoped DSP. Stop/restart, route changes, and capture replacement must still neutralize and release the effect through the existing lifecycle path.
