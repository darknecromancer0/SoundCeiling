# SoundCeiling v0.7.1 Linked Lock and Global Normalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make SoundCeiling audibly and measurably normalize allowed output so a whisper and a scream leave the speaker at nearly the same selected level, without Media-step sawtooth, while adding an enabled-by-default Default Linked Lock simple mode and preserving default exclusion of system apps and non-media system streams.

**Architecture:** Separate measurement, policy, desired output gain, and Android actuation. A pure control core consumes route-calibrated dB measurements and produces monotonic commands. DynamicsProcessing is preferred only when SoundCeiling has a documented trusted session handle, or when a global-mix effect is proven on the route and its indivisible scope is explicitly allowed. Stock third-party playback exposes neither session ID nor UID through public AudioPlaybackConfiguration, so YouTube/Yandex normally use the same core through a conservative Media-step fallback unless a truthful DSP tier becomes available. Android services own capture, trusted effect lifecycles, and telemetry but do not contain normalization math.

**Tech Stack:** Android Java 17, minSdk 29, compile/targetSdk 35, Android framework AudioPlaybackCapture/AudioManager/Visualizer/DynamicsProcessing, AndroidX Core 1.16.0, Gradle Kotlin DSL, pure-Java executable regression tests, shell source-contract tests, GitHub Actions.

**Spec:** docs/superpowers/specs/2026-08-22-v0.7.1-linked-lock-global-normalization-design.md

## Global Constraints

- [ ] Treat the approved design spec as normative. If implementation evidence contradicts it, update the spec and obtain approval before changing behavior.
- [ ] Keep system applications excluded by default. Keep only the MEDIA system stream enabled by default; calls, alarm, ringtone, notification, system, DTMF, accessibility, and assistant remain disabled until the user opts in.
- [ ] Never claim global DSP from effect construction alone. Capability becomes verified only after the route effect probe passes and either an OEM scope proof exists or the user explicitly opts the whole indivisible output scope in.
- [ ] Do not obtain third-party UID/session IDs by reflection, hidden API, dumpsys, guessing, or enumeration. Public AudioPlaybackConfiguration contributes AudioAttributes usage only.
- [ ] Policy uncertainty blocks positive gain and DSP attachment; it never blocks emergency attenuation needed to enforce a hard peak ceiling.
- [ ] Distinguish user Samsung-volume movement from SoundCeiling-owned writes with VolumeWriteTracker before changing Linked Lock state.
- [ ] Use real route step gain data when Android supplies it. Convert linear amplitude to dB before control math; never treat a linear float as dB.
- [ ] Keep all controller math pure Java and covered by deterministic tests. Android wrappers receive narrow commands from the core.
- [ ] A task is complete only after its RED test is observed, its GREEN test passes, the full pure suite passes, relevant source contracts pass, and the task has a focused commit.
- [ ] Do not mark device-only acceptance items passed from CI. Report them as awaiting Samsung field verification and ship diagnostics sufficient to verify them.
