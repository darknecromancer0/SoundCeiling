# SoundCeiling v0.4 Safety, Loudness, EQ and Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship SoundCeiling v0.4 with a fail-safe volume guard, first-block peak/transient protection, LUFS-like normalization, richer Simple/Advanced controls, presets/profiles, guided calibration, bounded diagnostics, optional EQ/DSP capability probing, themes and a new launcher icon.

**Architecture:** Keep the guaranteed safety path independent from optional audio effects. Measurement backends feed pure decision classes; every Media write passes one final safety pipeline before `VolumeApplier`. UI reads one runtime model, while EQ/DSP is capability-gated and may fail without disabling the core guard.

**Tech Stack:** Android Java, AudioManager/AudioPlaybackCapture, optional Visualizer/DynamicsProcessing/Equalizer, SharedPreferences, MediaStore logs, pure Java regression tests, GitHub Actions Gradle `assembleDebug`.

**Spec:** `docs/superpowers/specs/2026-08-21-v0.4-safety-loudness-eq-design.md` plus normative `docs/superpowers/specs/2026-08-21-v0.4-safety-loudness-eq-finalization.md`.

## Global Constraints
- Android 10+ remains supported.
- Safety Lock is the last independent clamp and defaults off.
- Minimum Media defaults to index 1; Maximum Media defaults to 70% of stream max.
- Manual user decreases outrank normalization and one-step changes must be detected.
- Emergency raw-peak/transient protection must not wait for the v0.3 ~250 ms RMS smoother.
- Optional DSP/EQ failure must preserve the Media guard.
- LUFS-like is labelled non-certified until validated against reference vectors.
- No automatic log upload; retained v0.4 log budget defaults to 16 MiB.
- Only approved low-level volume writers may call `setStreamVolume`.
