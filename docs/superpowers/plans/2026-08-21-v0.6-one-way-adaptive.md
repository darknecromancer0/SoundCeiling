# SoundCeiling v0.6.0 One-Way Adaptive Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bidirectional Samsung Media normalizer with a fast one-way adaptive engine that treats the user's Media slider as authoritative and can only HOLD or reduce it automatically.

**Architecture:** Preserve the proven v0.5 Hybrid Engine source/device/policy/capture layers, but replace the final control semantics with a monotonic-down Media path. Add explicit write-origin acknowledgement, a manual dB threshold follower, faster control loudness/transient paths, and truthful runtime diagnostics. UI, calibration, theme and log UX are adjusted around the same single engine rather than introducing another service.

**Tech Stack:** Android Java, AudioPlaybackCapture/MediaProjection, AudioManager, existing pure Java control math, SharedPreferences, SAF/MediaStore/FileProvider, GitHub Actions, javac pure tests and Gradle Android build.

**Spec:** `docs/superpowers/specs/2026-08-21-v0.6-one-way-adaptive-design.md`

## Global Constraints

- Automatic `STREAM_MUSIC` writes MUST satisfy `appliedIndex <= observedCurrentIndex`.
- Target is an upper comfort threshold; content below Target is HOLD, never UP.
- User movement below Minimum is accepted and never restored upward by SoundCeiling.
- Maximum and optional Safety Lock may clamp user movement downward immediately.
- Quiet Now is HOLD/DOWN only.
- Exact source identity is not required for Global PCM HOLD/DOWN control.
- App OFF/conflict rules and microphone-isolation invariants from v0.5 remain intact.
- Precise PlaybackCapture continues to require MediaProjection consent for a newly started exact PCM session.
- EQ is optional and independent from the safety path.
- Existing v0.5.1 preferences and user profiles migrate in place; obsolete upward timing fields are retained only for serialization compatibility and ignored by v0.6 runtime control.

- [ ] **Step 3: Add final automatic clamp that respects manual below-Minimum state**

Implement:

```java
static int clampAutomatic(int requested, int current, SafetySettings s,
                          int effectiveMax, boolean allowBelowMinimum) {
    int hardMax = Math.min(s.hardMax(), Math.max(0, effectiveMax));
    int upper = Math.min(current, hardMax);
    int floor = allowBelowMinimum ? 0 : Math.min(s.minIndex, current);
    return Math.max(floor, Math.min(upper, requested));
}
```

This means a user at Media 1 while configured Minimum is 3 remains at 1 if an old caller asks for 5.

- [ ] **Step 4: Route all Media writes through the new clamp**

`SafeVolumeController` re-reads current Media immediately before final clamping. It must never call `VolumeApplier.applyIndex()` with a value greater than that observed current value.
