# SoundCeiling v0.5 Source Evidence Plan Amendment

This amendment is normative for Tasks 6–8 of `2026-08-21-v0.5-hybrid-engine.md`.

## Why this amendment exists

The approved v0.5 safety rule blocks automatic raise whenever source identity is only `LIKELY`, `MIXED` or `UNKNOWN`. Public `AudioPlaybackConfiguration` is not a reliable package/UID oracle, so a source-evidence path is needed to avoid making Smart PCM upward normalization unusable for common media apps.

## Task 6 additions: package visibility

- Add `android.permission.QUERY_ALL_PACKAGES` for the current non-Play-focused engineering build so Apps search can enumerate installed apps broadly.
- Keep package name as the persistence key and resolve current UID from PackageManager at runtime.
- The future Google Play compliance pass may replace this permission strategy; v0.5 engineering architecture must not depend on Play policy constraints.

### Semantics

- Notification-listener access is optional. The user is never required to grant it for global Safety Lock/fallback behavior.
- The listener exists only to qualify for `MediaSessionManager.getActiveSessions(...)`; SoundCeiling does not use notification message content for audio control.
- One active playing MediaSession package is evidence for a candidate package, but remains `LIKELY` because another app may be producing audio without a media session.
- Multiple playing MediaSession packages produce `MIXED` candidate evidence.
- Absence of MediaSession evidence never proves silence or identifies another app.
- The UI must explain that this optional permission improves app/source detection, not microphone access.

### TDD gates

- [ ] A single MediaSession candidate resolves only to `LIKELY`, never directly to `EXACT`.
- [ ] Multiple candidates resolve to `MIXED`.
- [ ] Disabled notification-listener access degrades to playback activity only without breaking global safety.
- [ ] No notification text/content is persisted by SoundCeiling source-evidence code.

## Task 8 additions: candidate -> targeted PCM proof

When Task 7 produces one `LIKELY` package candidate:

1. resolve its current UID through `PackageSourceRepository`;
2. create a targeted `AudioPlaybackCaptureConfiguration` using `addMatchingUid(uid)`;
3. if valid non-silent PCM arrives while corroborated playback is active, source confidence may upgrade to `EXACT` for that package for the current evidence epoch;
4. if targeted PCM is empty/blocked/uncertain, do not upgrade confidence and do not auto-raise;
5. invalidate the proof when playback/source epoch changes, package UID changes, MediaProjection restarts, route/backends reset, or targeted capture stops being healthy.

A targeted capture must not be treated as proof that the UID is the only audible source if independent playback evidence indicates multiple simultaneous sources. In that case the result remains `MIXED` and auto-raise stays blocked.

## Release gate additions

CI/source contracts must ensure:

- MediaSession evidence cannot assign `EXACT` by itself.
- `EXACT` upgrade requires successful targeted UID PCM evidence plus no contradictory mixed-source evidence.
- Optional notification-listener access has a fail-closed fallback.
- QUERY_ALL_PACKAGES is documented as an engineering-build choice pending later Google Play policy work.
