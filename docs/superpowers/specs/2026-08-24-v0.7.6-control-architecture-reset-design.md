# SoundCeiling v0.7.6 · Control Architecture Reset

**Status:** approved in chat on 2026-08-24. Implementation is blocked until this written specification is reviewed.

**Branch / PR:** `feature/v0.7-adaptive-envelope`, draft PR #8.

## 1. Why v0.7.6 exists

v0.7.5.2 field testing on Samsung SM-A528B shows that the current fallback architecture is no longer a credible implementation of the original product goal.

The observed loop is:

1. Playback Capture sees source PCM peaks near 0…-2 dBFS even at low Samsung Media indices.
2. Global session-0 `DynamicsProcessing` is constructible but remains `AVAILABLE_UNVERIFIED`; no normal continuous DSP gain is therefore applied.
3. The controller treats source-domain peaks as if they were output-domain danger and selects `PEAK_EMERGENCY` / `MEDIA_INDEX` repeatedly.
4. Samsung Media becomes the fast limiter actuator and is driven 3→2→1.
5. A user attempt to restore 1→2 is often reversed within milliseconds by another `PEAK_EMERGENCY` 2→1.
6. The result is a sticky 1/15 limiter with little or no perceptual normalization, no useful positive normalization, and visible slider fighting.

The uploaded `SoundCeiling-20260824-050455.log.txt` demonstrates this directly: repeated hard-peak Media decisions dominate the session, Global DSP probes do not verify, and manual 1→2 changes are repeatedly followed by app-owned 2→1 emergency writes.

This is an architectural failure, not a tuning problem. v0.7.6 therefore changes the ownership and measurement model instead of adding another local recovery exception.

## 2. Product contract

The original contract is restored as the primary invariant:

> The Samsung Media slider is the user's master loudness anchor. SoundCeiling normalizes audio relative to that anchor without taking ownership of the slider during ordinary fast dynamics.

Consequences:

- The user may choose any Samsung Media step that is otherwise allowed by Safety Maximum.
- A manual user move takes effect immediately and becomes the new master anchor.
- Ordinary fast peak limiting, loudness attack, release and gain riding must not be implemented by rapidly moving Samsung Media.
- Verified DSP is the continuous actuator for both attenuation and amplification.
- If continuous DSP cannot be verified, SoundCeiling must degrade honestly to a slower coarse fallback rather than pretending Media steps are DSP.
- SoundCeiling must never keep forcing Media back to 1/15 merely because source PCM peaks approach 0 dBFS.
- Safety Maximum / explicit hard Media ceilings remain authoritative and may still clamp Media immediately when the system Media index itself violates a configured hard limit.

## 3. Three domains must never be conflated

v0.7.6 makes three level domains explicit in code and telemetry.

### 3.1 Source domain

Measured from Playback Capture before the output route when capture is PRE_VOLUME.

Contains:
- source peak;
- source RMS;
- source loudness / LUFS-like estimate;
- source activity / silence evidence.

A source peak near 0 dBFS is normal for mastered music. It is not by itself evidence that the user's speaker/headphone output is unsafe.

### 3.2 Output-estimate domain

Best available estimate of what reaches the active output route after Media gain and verified SoundCeiling DSP gain.

For proven PRE_VOLUME capture:

`projectedOutput = source + mediaRouteGain + verifiedDspGain`

For proven POST_VOLUME capture:

`projectedOutput = capturedOutput + verifiedDspGain`

For UNKNOWN capture reference, exact output projection is unavailable. The engine may use only evidence whose domain is explicitly known. It must not silently replace missing output evidence with raw source peak.

### 3.3 User-master domain

Samsung `STREAM_MUSIC` index plus its route curve.

This domain represents user intent and coarse hardware/output gain. It is not the high-frequency control signal for the normalizer.

## 4. Hard invariants

These are source-contract and regression-test requirements, not comments or recommendations.

1. **Raw/source peak cannot directly trigger a Media-index emergency when capture is PRE_VOLUME or UNKNOWN.**
2. **A PRE_VOLUME projected peak must include the active Samsung route gain.**
3. **Samsung Media cannot be the fast attack/release actuator for ordinary normalization.**
4. **A user 1→2 change cannot be reversed by ordinary source-peak logic.**
5. **Unverified DSP gain is never treated as applied gain.**
6. **Global DSP preference ON does not imply Global DSP capability.**
7. **Media fallback cannot claim continuous normalization.**
8. **Hard Media ceiling enforcement remains independent of DSP verification and may still move Media downward immediately if the current Media index itself exceeds the configured hard maximum.**
9. **Quiet Now remains downward-only and explicit.**
10. **App/system OFF policy remains fail-closed; a global effect is not allowed to override excluded system usages merely to obtain normalization.**

## 5. Actuator hierarchy

The coordinator selects actuators in this order.

### Tier A · Verified continuous DSP

Use verified route-scoped DSP for ordinary normalization.

Capabilities:
- continuous positive and negative gain;
- fast peak limiting without touching Samsung Media;
- smooth loudness attack/release;
- small corrections below a single Samsung step;
- no movement of the user master slider.

The existing preset timing remains the starting control envelope:
- LIGHT: 120 ms attenuation attack, 2500 ms upward release;
- MEDIUM: 80 ms attenuation attack, 1500 ms upward release;
- STRICT: 50 ms attenuation attack, 1000 ms upward release.

Peak protection inside verified DSP may react faster than the loudness envelope, but must release through a smoothed gain path instead of stepping Media.

### Tier B · Stable coarse Media fallback

Used only when continuous DSP is unavailable or unverified and output-domain evidence is sufficient for a safe coarse correction.

Rules:
- Media is a slow trim, not a sample/block-level limiter.
- Maximum movement is one Samsung step per committed fallback decision.
- Ordinary fallback decisions require sustained loudness imbalance, not a single raw PCM peak.
- Fallback has a minimum dwell between writes. The initial design target is at least 1000 ms in MEDIUM, with preset-specific tuning allowed later only after field evidence.
- Recovery may repay only app-owned attenuation up to the current user anchor.
- A manual user move cancels pending coarse recovery and immediately rebases the anchor.
- A fallback correction must never ping-pong against a user move within the same control epoch.
- At floor/minimum, repeated requests for impossible downward steps are converted to HOLD and rate-limited diagnostics, not repeated actuator spam.

Tier B is displayed/logged as **Coarse Media fallback**.

### Tier C · Safety-only

If output-domain loudness cannot be estimated safely:
- retain hard Media ceiling enforcement;
- retain explicit Quiet Now;
- retain policy/source diagnostics;
- do not invent normalization or repeatedly move Media from source-domain peaks.

## 6. Global DSP verification redesign

The current three-sample before/after RMS probe is too sensitive to the changing music signal. v0.7.6 replaces it with source-compensated differential verification.

Android public API facts used by this design:
- `DynamicsProcessing` is an `AudioEffect` attached by audio session ID and supports realtime gain/compressor/limiter parameters.
- Global insert effects through session 0 are deprecated and therefore treated as OEM-dependent capability, never assumed.
- `Visualizer(0)` observes the audio output mix.
- `Visualizer.SCALING_MODE_AS_PLAYED` makes playback volume affect the captured level, making it useful as output-domain evidence when available.

### 6.1 Probe inputs

During one stable targeted Playback Capture epoch collect synchronized or near-synchronized pairs:

`sourceRms(t)` from Playback Capture

`outputRms(t)` from `Visualizer(0)` configured for `SCALING_MODE_AS_PLAYED` + `MEASUREMENT_MODE_PEAK_RMS` when the OEM supports them.

Define the route residual:

`residual(t) = outputRms(t) - sourceRms(t)`

The residual cancels much of the natural music-level variation because both meters observe the same changing program at approximately the same time.

### 6.2 Bounded differential probe

1. Verify stable active program, stable Media index, stable output route and no source/capture transition.
2. Collect a baseline residual window.
3. Apply the bounded `-2 dB` candidate DSP probe.
4. Collect an active-probe residual window.
5. Neutralize DSP to exactly 0 dB before classification.
6. Compare robust statistics of the two residual windows, using median/trimmed evidence rather than three raw samples.
7. Promote only if the residual shift is consistently negative and close enough to the requested probe to reject normal meter noise.

Initial acceptance band for a `-2 dB` probe:
- minimum observed differential effect: `-1.0 dB`;
- maximum plausible magnitude: `-3.0 dB`;
- enough valid paired samples to cover at least 250 ms of stable program;
- no Media index change, route change, capture rebind, silence transition or policy conflict inside the evidence window.

A failed/ambiguous probe stays `AVAILABLE_UNVERIFIED`; it does not activate DSP.

### 6.3 Verification lifecycle

Verification is keyed by physical output route and transport generation, not mixed/targeted capture identity.

Invalidate and neutralize on:
- physical route change;
- effect control loss / dead object;
- DSP re-creation;
- policy incompatibility with the global scope;
- impossible/stale output meter evidence.

A mixed↔targeted Playback Capture rebind cancels an in-flight measurement window but does not by itself prove that the physical DSP route changed.

## 7. Continuous DSP controller

After DSP is VERIFIED, ordinary normalization happens entirely in continuous gain space.

Inputs:
- source loudness estimate;
- projected/output loudness evidence where available;
- source peak;
- projected output peak;
- target / linked ceilings;
- current verified DSP gain;
- policy and source confidence.

Behavior:
- Loud material is attenuated toward target using preset attack/strength.
- Quiet material is amplified toward target using preset release/strength.
- Positive gain is capped by headroom so the predicted post-DSP peak does not cross the configured peak ceiling.
- Peak limiter attenuation is a DSP gain/limiter action, not a Samsung Media action.
- Gain changes are slew-limited/smoothed to avoid audible pumping and zippering.
- User Media movement does not rewrite DSP target history as an app-owned action; it reanchors desired output and the controller converges smoothly from the new point.

The control loop may run at PCM-block cadence, but user-visible/log summary events remain rate-limited.

## 8. Linked Lock semantics

Default Linked Lock remains ON by default in Simple and Advanced.

When ON:
- Samsung Media is the user's master anchor.
- The linked desired output point moves only on proven USER Media changes or explicit UI changes.
- DSP gain changes never move linked ceilings.
- Coarse Media fallback writes never move linked ceilings.
- Minimum/Maximum Output Ceiling remain visible but disabled/dimmed.

When OFF:
- manual ceiling controls unlock in both Simple and Advanced;
- changing them does not move Samsung Media immediately;
- the actuator hierarchy remains unchanged.

## 9. Safety semantics

v0.7.6 separates four safety cases.

### 9.1 Hard Media ceiling

If current `STREAM_MUSIC` itself exceeds configured Safety Maximum, immediate downward Media enforcement remains legal and independent of DSP.

### 9.2 Verified projected-output peak

If output-domain evidence predicts a peak violation:
- verified DSP handles it continuously when available;
- without verified DSP, a coarse Media fallback may reduce one step only when the projected output after that step is meaningfully safer and the decision is based on output-domain evidence, not raw source peak.

### 9.3 Source peak only

Source peak alone is diagnostic/headroom evidence. It cannot generate `PEAK_EMERGENCY -> MEDIA_INDEX` in PRE_VOLUME/UNKNOWN mode.

### 9.4 Auto mute

`Auto mute=false` preserves the configured Media floor. `Auto mute=true` may explicitly permit a safety path below that floor. This does not change the source/output-domain rules above.

## 10. Source and policy handling

- Targeted Playback Capture remains the strongest source identity proof available to the current no-root build.
- UNKNOWN/LIKELY/EXACT source confidence affects per-app policy and positive-gain permission, but does not redefine physical measurement domains.
- Global DSP may activate only when its whole affected scope is policy-compatible.
- Default-OFF system usages remain excluded unless the user explicitly opts them in.
- If policy compatibility is not provable for a global effect, neutralize it and use a compatible lower tier.

## 11. State model and ownership

The current shared coordinator state is split conceptually into explicit owners:

- `UserMasterState`: user anchor, user-write epoch, manual-pause/rebase state.
- `OutputModel`: capture reference, Media route gain, output meter confidence, projected peak/loudness.
- `DspTransportState`: constructed/verified/active, route generation, applied gain.
- `NormalizationState`: target error, smoothed desired gain, attack/release/hold state.
- `MediaFallbackState`: app-owned attenuation debt, dwell, pending one-step write, recovery authority.
- `SafetyState`: hard Media max/floor, peak ceiling, Quiet Now, Auto mute.

A state transition in one owner must not silently mutate another owner. In particular:
- app Media write does not become user anchor;
- DSP gain does not move linked ceilings;
- capture rebind does not become physical route change;
- raw source peak does not become projected output peak.

## 12. Diagnostics required before device claims

Add transition/rate-limited fields sufficient to reconstruct the control decision without huge per-block spam:

- `meterDomain=SOURCE|OUTPUT|PROJECTED|UNKNOWN`
- `sourcePeak`, `sourceLoudness`
- `mediaRouteGainDb`
- `projectedOutputPeak`, `projectedOutputLoudness`
- `dspState=UNAVAILABLE|AVAILABLE_UNVERIFIED|VERIFIED|ACTIVE`
- `dspRequestedGainDb`, `dspAppliedGainDb`
- `actuatorTier=DSP|COARSE_MEDIA|SAFETY_ONLY`
- `mediaAnchor`, `mediaDebt`, `mediaDwellRemainingMs`
- `decisionReason`

New dedicated events:
- `dsp_differential_probe_begin`
- `dsp_differential_probe_result`
- `dsp_verification_invalidated`
- `coarse_media_write`
- `coarse_media_hold`
- `raw_peak_not_output_emergency` (rate limited, diagnostic only)

## 13. Required regressions

No implementation task is complete until deterministic regressions cover these field-derived cases.

1. **Low-volume mastered music:** Media 1/15, PRE_VOLUME source peak 0 dBFS, Samsung route gain about -53 dB -> no Media emergency from raw peak.
2. **User authority:** user 1→2 during active music -> no immediate app 2→1 unless an independently verified output-domain safety violation exists.
3. **Projected peak correctness:** PRE_VOLUME projected peak includes route gain; POST_VOLUME does not double-apply it.
4. **UNKNOWN fail-closed:** UNKNOWN reference cannot substitute raw peak for output peak.
5. **DSP differential proof:** changing source level with no real DSP effect does not verify; a synthetic -2 dB output residual shift does verify.
6. **Probe lifecycle:** Media move/rebind/route change during the evidence window cancels proof and neutralizes.
7. **Verified DSP normalization:** loud then quiet synthetic PCM changes DSP gain in both directions while Media stays unchanged.
8. **DSP peak limiter:** projected peak violation attenuates DSP without touching Media.
9. **Coarse fallback:** no verified DSP + sustained loudness imbalance -> at most one Media step after dwell.
10. **No fast fallback:** transient/source peak alone cannot trigger repeated Media writes.
11. **Fallback recovery:** app-owned Media attenuation may recover one step at a time up to user anchor after sustained opposite error and dwell.
12. **Floor hold:** at Media floor, impossible downward requests are HOLD, not repeated writes.
13. **Hard Media max:** user/system index above hard max is still clamped immediately.
14. **Quiet Now:** stays explicit downward-only.
15. **Linked Lock provenance:** USER Media move shifts linked target; DSP/coarse fallback writes do not.
16. **Policy conflict:** global DSP neutralizes before entering a lower tier when excluded usage/source makes scope incompatible.
17. **Stop/restart:** v0.7.4.1/v0.7.4.2 teardown regressions stay green.

## 14. Samsung SM-A528B acceptance test

The first v0.7.6 APK is not considered functionally accepted until a physical test demonstrates all of the following:

1. Put Samsung Media at 1/15 or 2/15 and play Yandex Music/YouTube.
2. During normal mastered peaks near 0 dBFS, the Samsung slider remains at the user's chosen index unless a genuine hard Media ceiling is violated.
3. Manual 1→2, 2→3, 3→2 changes remain where the user puts them; no millisecond snap-back from raw peak.
4. If Global DSP verifies, logs show `VERIFIED/ACTIVE` and audible loud/quiet passages are normalized through changing DSP gain while Media stays fixed.
5. If Global DSP does not verify, UI/logs clearly state Coarse Media fallback; the slider may move only slowly by isolated one-step corrections, not block-by-block.
6. No sticky 1/15 behavior after app-owned attenuation; recovery never exceeds the current user anchor.
7. Stop/restart remains crash-free over at least 10 cycles.

The most important acceptance criterion is perceptual: with verified DSP, a quiet passage and a loud passage should converge substantially toward the same perceived output level without visible Samsung slider motion.

## 15. Scope exclusions

v0.7.6 does not add:
- root/Shizuku transport;
- hidden API/session-ID scanning;
- microphone-based production normalization;
- system-wide processing claims that cannot be verified;
- a new UI redesign unrelated to truthful capability/status display.

If public session-0 DSP cannot be verified on SM-A528B after the redesigned differential probe, privileged audio transport becomes a separate future design decision rather than another fallback hack.

## 16. Implementation boundary

This design intentionally replaces the current control assumption rather than layering another exception on it.

Expected implementation areas:
- output-domain measurement / projection model;
- DSP differential verifier;
- continuous DSP gain controller path;
- coordinator actuator selection;
- slow Media fallback state machine;
- user-master provenance boundary;
- diagnostics and status copy;
- field-derived regression suite and release contract.

The existing source recognition, app/system policy UI, Linked Lock UI, logging storage, calibration UI, stop lifecycle fixes and general navigation are preserved unless a regression proves they must change.

## 17. Version / release policy

- Target version: `0.7.6`.
- Continue on `feature/v0.7-adaptive-envelope` / PR #8.
- Write RED field regressions before production changes.
- Do not weaken historical safety/user-authority contracts merely to make new tests pass; supersede only contracts whose old behavior directly contradicts this approved architecture and document the reason.
- Final APK must come from one immutable GitHub Actions HEAD with pure regressions, source contracts, Android `assembleDebug`, checksum and artifact upload all green.
- CI success does not equal physical normalization success. Samsung device status remains `awaiting device test` until the acceptance test above passes.
