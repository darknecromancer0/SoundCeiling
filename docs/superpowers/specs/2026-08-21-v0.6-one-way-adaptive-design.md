# SoundCeiling v0.6.0 One-Way Adaptive Engine Design

## Status

Approved direction: Variant B, One-Way Adaptive Engine.

## Goal

Make SoundCeiling behave like a fast, predictable, down-only playback safety controller instead of an automatic Samsung Media-volume normalizer that fights the user.

The system Media slider is the user's master control. SoundCeiling may hold it or lower it when safety/normalization rules require, but automatic code must never raise it.

This intentionally changes Target semantics from bidirectional normalization to an upper comfort target: quiet playback below Target is held, not boosted through the Samsung Media slider; playback above Target may be reduced.

## Primary invariants

1. Automatic Media writes are monotonic downward: every controller-origin write must satisfy `appliedIndex <= observedCurrentIndex`.
2. User-origin volume changes are never reversed upward by SoundCeiling.
3. Minimum Media is only the floor for automatic downward control. If the user manually sets Media below Minimum, SoundCeiling does not raise it back to Minimum.
4. Maximum Media is a hard user/system cap. If the user tries to go above it, SoundCeiling may immediately clamp downward to the maximum.
5. Quiet Now is strictly downward-only: `target = min(current, configuredQuietIndex)`.
6. Safety Lock remains an absolute hard cap for both user and automatic paths.
7. Peak/transient emergency control may bypass normal timing and immediately lower Media.
8. Ordinary loudness normalization may only hold or lower Media. It never raises Media.
9. Exact app identity is not required for Global PCM control. Exact identity is required only for app-specific rules that depend on knowing the source.
10. Automatic writes must never be reclassified as user intent.
11. Microphone input remains outside SoundCeiling control.

## Why v0.5.1 is being replaced

Observed test logs show all of the following:

- manual decreases are followed by `comfort_upward` writes that restore Media upward;
- `ManualSafetyController` intentionally re-opens its effective maximum after a decrease;
- `HybridEngineCoordinator` still contains a `comfort_upward` branch;
- some controller writes to zero are later logged as external/unexpected zero, contaminating diagnostics and user-intent tracking;
- emergency detection-to-write can already be very fast once an event is recognized, so the remaining perceived latency is primarily detection/windowing latency;
- Simple and Advanced are two views of one engine, but current copy makes them look like separately active modes;
- MediaProjection is still required for precise AudioPlaybackCapture PCM sessions;
- calibration tone sequencing is indirect and can fail to start cleanly;
- status-card colors are hard-coded for dark presentation;
- Logs navigation still exposes separate actions that should be consolidated.

## Engine architecture

### 1. User master volume

The current Android `STREAM_MUSIC` index is authoritative user intent unless the latest observed value is an acknowledgement of a recent SoundCeiling write.

The controller has no automatic upward authority.

Any request from normalizer/coordinator/safety logic is passed through a final invariant clamp:

`automaticRequestedIndex = min(observedCurrentIndex, automaticRequestedIndex)`

This clamp is enforced in the final Media-write layer as well as in higher-level policies.

### 2. VolumeWriteTracker

Add a dedicated write-origin tracker.

Before every SoundCeiling Media write, record:

- origin: `NORMALIZER_DOWN`, `PEAK_EMERGENCY`, `TRANSIENT_EMERGENCY`, `HARD_CAP`, or `QUIET_NOW`;
- expected index;
- previous observed index;
- elapsed timestamp;
- acknowledgement deadline.

ToneController does not write Media in v0.6 and therefore has no Media-write origin.

When the volume observer receives a new system index:

- if it matches a pending expected index within the acknowledgement window, classify it as `APP_WRITE_ACK`;
- otherwise classify it as `USER_CHANGE` or `EXTERNAL_CHANGE` according to context;
- an acknowledged SoundCeiling write must not update manual-user thresholds or trigger `external_zero_detected`.

Default acknowledgement window: 250 ms.

### 3. Manual dB threshold follower

Manual Media movement changes effective dB thresholds without causing automatic Media restoration.

Track `manualThresholdOffsetDb <= 0` relative to configured settings.

When the user lowers Media from index A to B:

`deltaDb = curve.gainDbForIndex(B) - curve.gainDbForIndex(A)`

For a decrease, `deltaDb` is negative. Add it to the desired manual threshold offset.

Apply the offset to effective thresholds:

- `effectiveTargetLoudness = configuredTargetLoudness + manualThresholdOffsetDb`
- `effectivePeakCeiling = configuredPeakCeiling + manualThresholdOffsetDb`
- `effectiveSplTarget = configuredSplTarget + manualThresholdOffsetDb` when calibrated SPL mode is active
- `effectiveSplCeiling = configuredSplCeiling + manualThresholdOffsetDb` when calibrated SPL mode is active

Transient delta thresholds stay relative and do not receive this offset.

Smoothing defaults:

- follow a manual decrease toward the more-negative desired offset with a 120 ms time constant;
- when the user manually raises Media, restore the offset toward 0 with a 650 ms time constant;
- restoring thresholds never moves the Media slider.

If the user reaches stream minimum/mute, ordinary normalization pauses until the user raises Media manually. Hard caps and emergency downward logic may remain armed, but no automatic upward recovery exists.

### 4. Minimum, Maximum and Safety Lock semantics

`Minimum Media`:

- automatic loudness/transient reduction normally stops at Minimum;
- manual user movement below Minimum is accepted and never undone;
- Auto Mute, if explicitly enabled, may permit emergency reduction below Minimum down to 0.

`Maximum Media`:

- absolute normal Media cap;
- user movement above Maximum is clamped immediately downward;
- it does not cause any automatic upward movement when current is below Maximum.

`Safety Lock`:

- optional additional hard cap, never above Maximum;
- effective hard max is the stricter of Maximum and Safety Lock;
- user attempts above this hard max are clamped downward immediately.

Impossible combinations are normalized at save time and at service reload time.

### 5. Quiet Now

Quiet Now is a dedicated downward command.

`quietTarget = min(currentIndex, configuredQuietIndex, effectiveHardMax)`

If `quietTarget == currentIndex`, no Media write occurs.

Quiet Now must never use Minimum as a reason to raise Media.

When Quiet Now actually lowers Media, the threshold follower receives the same negative control-curve delta as a deliberate safe lowering, but the resulting Android volume acknowledgement remains classified as `APP_WRITE_ACK`, not `USER_CHANGE`. The app remains down-only. The user can later raise Media manually, which gradually restores threshold offset toward configured values.

### 6. Fast PCM safety path

PlaybackCapture remains the preferred PCM backend where Android allows it.

Use approximately 10 ms PCM blocks for raw peak measurements.

Emergency raw-peak evaluation happens for every available block and does not wait for loudness/RMS smoothing.

For an emergency:

1. calculate projected output peak using source peak plus current Samsung control-curve gain;
2. calculate the highest safe index whose gain keeps projected output at/below the effective ceiling;
3. apply that lower index immediately in one write;
4. log detection-to-write latency.

No downward attack delay applies to peak emergency.

### 7. Transient protection

Transient detection remains edge/re-arm based rather than permanent-latch based.

Use short adaptive windows rather than waiting for the slow loudness estimator.

Default behavior:

- analysis cadence: every PCM block;
- short baseline horizon: approximately 40-60 ms;
- transient warning is diagnostic/soft behavior;
- transient emergency may cause an immediate downward write;
- emergency target is calculated from required attenuation rather than a fixed number of Samsung steps.

A sustained high level must re-arm and stop being classified as a new transient on every block.

### 8. Ordinary loudness normalization

Loudness normalization is one-way.

The controller estimates output loudness from source LUFS-like plus current Media curve gain.

If output loudness is below target/deadband:

- return HOLD;
- never return UP.

If output loudness exceeds target + tolerance:

- calculate desired attenuation;
- apply `normalizationStrength` as the fraction of the correction to take during this decision;
- convert resulting gain to the nearest safe lower/equal Media index;
- request HOLD or DOWN only.

Default decision window should be materially shorter than v0.5.1 and target responsive control in the 50-80 ms loudness range while raw peak/transient protection remains faster.

`Normalization strength` meaning:

- 0%: ordinary loudness normalization disabled;
- 100%: request the full calculated downward correction immediately;
- intermediate values: partial correction.

### 9. Global PCM versus app identity

Healthy PCM can drive Global settings even when source package is unknown.

Global down-only control requires:

- PCM ACTIVE;
- healthy metering;
- no known conflict with an explicitly ignored source.

Exact source/package confidence remains required for per-app Custom/ON/OFF decisions that depend on identity.

Known multi-source conflict remains conservative. If control is shared and one source is explicitly OFF, source-specific normalization must not affect the shared mix unless isolation is proven. Global hard caps remain independent.

## MediaProjection and fallback

Precise AudioPlaybackCapture still requires Android MediaProjection consent for each new capture session under current Android behavior.

UI behavior:

- switching between Main, Advanced, EQ, Logs, Calibration, Apps, or Diagnostics must not restart an already-running PCM session;
- the projection dialog is requested only when starting a new precise PCM session;
- before requesting it, SoundCeiling explains that Android calls this screen capture permission even though SoundCeiling is using it to read playback audio PCM and does not store screen video;
- if denied, Safe Fallback can start, but UI must label that mode clearly and must not claim precise PCM control.

## UI model

Simple and Advanced are not separate running modes.

Keep destination keys for migration, but change user-facing labels to:

- `Основное`
- `Расширенные`

Both display one global engine status: `SoundCeiling: запущен` or `SoundCeiling: остановлен`.

Navigating between them never starts/stops/reconfigures the service by itself.

## Main / Simple layout

Keep current Simple design substantially intact.

Top controls:

- Start/Stop
- Quiet Now with a `?` explanation
- Target
- Minimum Media
- Maximum Media
- Normalization strength
- status card

Remove wording `только понизить` from the visible Quiet Now label. The help dialog explains that it can only reduce/hold and never raise.

Target help explicitly says that Target is an upper comfort target in v0.6: lowering Target makes SoundCeiling reduce loud playback sooner/more; raising Target allows more loudness before reduction; it never boosts quiet playback through the Samsung slider.

## Advanced layout

Order:

1. existing diagnostics/status card;
2. Profiles;
3. Start/Stop;
4. Quiet Now + `?`;
5. Target and Normalization;
6. Media boundaries and Safety Lock;
7. Peak and Transient protection;
8. reaction/sensitivity controls that still have meaning in a down-only engine;
9. optional SPL controls;
10. terminology/help;
11. live meters/frequency visualization and last-decision details.

Remove upward-only controls from the active UI:

- Upward release;
- Max up steps;
- automatic upward recovery controls.

Legacy preference values may remain only for migration compatibility and must not influence v0.6 control behavior.

Behavior presets include `Custom` and only configure parameters that still affect down-only control.

Every significant Advanced slider receives plain-language `?` help and a concise live effect/status where useful.

## Help terminology

Explain in ordinary language:

- PCM: raw digital samples SoundCeiling can analyze when Android/source permits it;
- Peak: the loudest instant sample/short instant, used for emergency protection;
- RMS: short-term average signal energy, not perceived loudness;
- dBFS: digital level relative to the maximum representable digital signal, where 0 dBFS is the digital ceiling;
- LUFS-like: SoundCeiling's approximate realtime loudness estimate, not standardized true LUFS measurement;
- dB SPL: estimated physical acoustic loudness, only meaningful after device/output calibration;
- DSP: signal processing. Status must distinguish analysis-only from actual output DSP transport;
- Transient: a sudden short increase relative to recent signal history;
- Target: the upper comfort loudness threshold above which one-way normalization may reduce playback. It never causes automatic Media increases.

## Apps & System Sounds layout

Order the page as:

1. System sounds section;
2. Applications heading;
3. search field immediately below Applications heading;
4. app filters;
5. app list.

Installed-app enumeration remains off the UI thread and must not block opening the screen.

## Calibration

Calibration is optional and only affects dB SPL estimation/control.

Normal LUFS-like/dBFS/Peak operation works without calibration.

Tone sequence is an explicit state machine:

`IDLE -> STOPPING_ENGINE (if needed) -> WAITING_STOPPED -> STARTING_TONE -> PLAYING_TONE -> COMPLETE/ERROR`

The calibration tone never writes `STREAM_MUSIC` in v0.6. It neither raises nor lowers the system Media slider and therefore never needs a restore write.

If current Media is too low to hear the tone, show a clear message asking the user to raise Media manually and retry.

Tone logging must include:

- `tone_request`
- `tone_waiting_engine_stop`
- `tone_started`
- `tone_complete`
- `tone_error`
- routed device and playback index

If the engine does not reach stopped state within a bounded timeout, show an error instead of silently doing nothing.

## Theme

Replace hard-coded status colors with semantic palette values in `UiTheme`:

- background/surface;
- primary/secondary text;
- success surface/text;
- warning surface/text;
- error surface/text;
- neutral status surface/text.

Light theme uses light-tinted status surfaces with dark readable text. Dark theme uses dark surfaces with high-contrast light text.

`UiTheme.applyToTree()` must not indiscriminately recolor every ViewGroup background. Components own their surface roles explicitly.

## EQ

EQ remains independent from SoundCeiling engine running state and independent from Main/Advanced navigation.

Supported combinations:

- EQ only;
- EQ + Main;
- EQ + Advanced.

Persistent EQ state is owned by an application-level controller, not by `EqView` lifecycle.

Keep linked-band behavior:

- user can select linked bands;
- Link Strength from 0-100%;
- moving one selected band moves other selected bands proportionally to link strength;
- unlinked bands remain unchanged;
- final values are clamped to EQ range.

If the OEM does not permit global EQ, show that capability as unavailable without affecting safety control.

## Logs

Drawer contains one Logs entry, not separate Open Logs and Share Last Log entries.

Logs screen contains:

- active location;
- `Открыть папку`;
- `Выбрать папку`;
- `Default location`;
- `Поделиться последней сессией`;
- logical session list.

Default location remains `Downloads/SoundCeilingLogs`.

`Открыть папку`:

- for a persisted custom SAF tree, try to open that tree;
- for default location, try to open the external-storage document URI for `Downloads/SoundCeilingLogs`;
- if the OEM/file manager cannot open that folder directly, fall back to the internal Log Sessions screen and explain that Android prevented direct folder navigation;
- it must never launch the folder chooser as the meaning of Open Folder.

`Поделиться последней сессией`:

- merge all rotated physical parts of the latest logical session into one temporary `.log` file under app cache;
- share one URI through FileProvider;
- keep individual session share/delete/open controls in the session list.

Retention continues to operate on logical sessions, never orphaning arbitrary part files.

## Diagnostics and logging

Volume-change diagnostics must make every write explainable.

For each real Media write log:

- origin;
- observed current index;
- requested index;
- final guarded index;
- applied index after re-read;
- configured Minimum/Maximum/Safety Lock;
- manual threshold offset dB;
- configured/effective Target;
- configured/effective Peak ceiling;
- raw source peak;
- projected output peak;
- source LUFS-like;
- PCM state/capability;
- source identity/confidence when available;
- detection-to-write latency for emergency paths.

Add compact transitions for:

- user volume down/up;
- app write acknowledged;
- automatic write mismatch;
- manual threshold offset change;
- normalization DOWN/HOLD reason;
- emergency detection and target calculation;
- MediaProjection request/start/deny/fallback;
- tone state transitions.

Do not log unchanged 10 ms decisions continuously. Keep high-rate data in the existing ring buffer and flush context around anomalies/real writes.

`external_zero_detected` is emitted only when zero cannot be explained by a recent acknowledged SoundCeiling write or explicit user action.

## Runtime status

Advanced/Diagnostics expose:

- PCM state;
- current source metering age;
- configured Target;
- effective Target after manual offset;
- configured Peak ceiling;
- effective Peak ceiling;
- manual threshold offset;
- current Media index;
- effective hard max;
- last controller action: HOLD/DOWN/CAP/QUIET;
- last reason;
- last emergency latency;
- active backend and fallback status.

There is no automatic `UP` controller action in v0.6.

## Migration

Upgrade existing v0.5.1 preferences in place.

- preserve Target, normalization strength, tolerance, Min/Max, Safety Lock, Peak/Transient, EQ, device profiles, app rules, calibration and theme;
- legacy upward release/max-up/recovery preferences are ignored by the v0.6 engine;
- preserve stored presets where possible, mapping their downward-relevant fields into v0.6 equivalents;
- reset manual threshold offset to 0 on upgrade/start because it is runtime user state, not durable preference.

## Required regression tests

Pure/controller tests must prove:

1. automatic normalizer can never request above current Media;
2. coordinator/final writer clamp any accidental automatic upward request to current;
3. manual `3 -> 2` followed by loudness below Target remains at 2;
4. manual repeated downward drag is never fought upward;
5. manual decrease updates desired negative dB threshold offset using the control curve;
6. manual raise restores threshold offset toward 0 without automatic Media movement;
7. Minimum does not raise a manually lower Media index;
8. Maximum/Safety Lock clamp upward user attempts downward immediately;
9. Quiet Now from below configured quiet level is HOLD, never UP;
10. acknowledged automatic writes are not treated as user changes;
11. acknowledged automatic zero does not generate `external_zero_detected`;
12. peak emergency chooses an index from projected output peak;
13. transient sustained content re-arms rather than repeatedly firing emergency;
14. emergency path bypasses ordinary attack timing;
15. unknown source with healthy Global PCM can still perform HOLD/DOWN normalization;
16. known OFF-source conflict blocks source-specific shared normalization;
17. calibration tone never writes Media;
18. EQ link strength math remains proportional and clamped.

Android/source/UI contracts must prove:

- no automatic Media write path can raise `STREAM_MUSIC`;
- Apps enumeration is worker-threaded;
- one Logs navigation entry only;
- Open Folder is not implemented as `ACTION_OPEN_DOCUMENT_TREE`;
- calibration tone state machine has timeout/error handling;
- light/dark semantic status palettes exist;
- Simple/Advanced user-facing copy no longer implies two separately running engines;
- MediaProjection is not re-requested merely when changing tabs;
- release metadata is v0.6.0.

## Device acceptance criteria

On the Samsung test device, a successful v0.6 build must demonstrate:

1. manually lowering Media never causes SoundCeiling to raise it again;
2. effective Target/ceiling move downward with a manual decrease and recover only when the user manually raises volume;
3. quiet audio is not automatically boosted through the Samsung slider;
4. loud audio can be reduced by normalization;
5. emergency peak/transient reduction is visibly fast and does not wait for the ordinary loudness window;
6. Maximum/Safety Lock still block user attempts above configured caps;
7. Minimum does not become a working-volume lock;
8. Quiet Now only lowers/holds;
9. Advanced clearly shows why each controller decision was HOLD/DOWN/CAP/QUIET;
10. changing Main/Advanced/EQ tabs does not trigger another projection request;
11. calibration tone audibly plays or produces an explicit actionable error;
12. Apps & System Sounds opens immediately and search is visually adjacent to apps;
13. light theme status cards remain readable;
14. Logs has one navigation entry, can share the latest logical session as one file, and best-effort opens the actual active folder;
15. no unexplained oscillation or `external_zero_detected` spam appears for SoundCeiling's own writes.

## Non-goals for v0.6

- true system-wide sample replacement DSP for arbitrary third-party playback;
- root/Shizuku Deep DSP engine;
- Google Play policy optimization;
- new major audio features unrelated to stabilizing the existing engine/UI.
