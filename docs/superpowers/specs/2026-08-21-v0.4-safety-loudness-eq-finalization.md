# SoundCeiling v0.4 — Finalized defaults and backend rules

This document is normative and supplements `2026-08-21-v0.4-safety-loudness-eq-design.md`. Where wording differs, this file wins.

## Measurement/control backends
v0.4 must probe capabilities at runtime in this order and show the result in Diagnostics.

### Tier A — verified pre/output-path DSP
Use a DynamicsProcessing/compatible limiter only if SoundCeiling can prove it controls the relevant audio path. This is the only tier that may be described as pre-output limiting. Failure or loss of control instantly disables the optional DSP and falls back to the Media guard.

### Tier B1 — global Visualizer safety backend
Attempt `Visualizer(0)` on the global output mix with `SCALING_MODE_AS_PLAYED` and `MEASUREMENT_MODE_PEAK_RMS`. Android documents session 0 as the output mix. This path needs `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS`, but does not require the MediaProjection capture dialog.

Use it for:
- output-mix peak/RMS monitoring;
- fast safety detection;
- coarse waveform/FFT visualization;
- basic operation when the user does not want MediaProjection.

Do not describe Visualizer waveform as full-quality recording. It is low-quality/partial by Android design. If initialization or continuous measurement fails, mark yellow and fall back.

### Tier B2 — AudioPlaybackCapture precision backend
When the user grants MediaProjection, use AudioPlaybackCapture for full PCM analysis, LUFS-like/K-weighted loudness, high-quality band analysis and detailed diagnostics. This backend requires Android's MediaProjection approval and `RECORD_AUDIO` and can only capture apps/usages allowed by Android capture policy.

Tier B1 and B2 may run together: Visualizer can be the fast safety watcher while PlaybackCapture provides precision analysis. If B1 is unavailable, B2 still provides fast raw-block peak protection.

### Tier C — Media-only guard
If neither measurement backend is available, enforce min/max/Safety Lock/manual override rules only. Never auto-raise based on unknown loudness. Diagnostics shows degraded protection.

## Loudness meter requirement
A lightweight K-weighted short-term loudness implementation is required in v0.4. Until it is validated against reference vectors, the UI label is `LUFS-like`, not certified `LUFS`. RMS remains visible for diagnostics but is not the primary normalization target.

## Relative transient guard
In addition to absolute/projected peak protection, v0.4 includes a sudden-change guard. Compare the current fast peak/loudness against a recent rolling baseline. A sufficiently abrupt upward jump may immediately shrink the effective Media ceiling before the slower normalizer catches up.

Defaults:
- transient warning delta: +6 dB;
- transient emergency delta: +10 dB;
- warning action: shrink effective maximum by 1 Media step;
- emergency action: calculate the safe target immediately, permitting a multi-step decrease down to configured minimum;
- recovery uses the normal slow/manual-safe release and never jumps upward.

## Stable default values
All values are code constants, shown in help text, used on first run, and restored by `Reset to defaults`.

### Global/default profile
- active normalization preset: **Medium**
- Minimum Media: **1 index**
- Maximum Media: **70% of stream maximum**
- Safety Lock: **Off**
- when Safety Lock is first enabled: initialise its value to current Maximum Media
- Quiet now target: **1 index**
- source/projected peak protection: **On**
- transient guard: **On**
- auto mute: **Off**
- user recovery step: **1 Media index**
- user recovery interval: **750 ms**
- theme: **System**
- log budget: **16 MiB total**

### Normalization preset values
The emergency raw-peak/transient guard is independent of these timings and may decrease in the same measurement cycle.

**Light**
- target loudness: **-20 LUFS-like**
- tolerance: **±4 LU**
- strength: **35%**
- normal downward attack: **120 ms**
- upward release interval: **2500 ms**
- hold after loud event: **1500 ms**
- max normal downward step: **1 Media index**
- max upward step: **1 Media index**

**Medium**
- target loudness: **-18 LUFS-like**
- tolerance: **±2.5 LU**
- strength: **65%**
- normal downward attack: **80 ms**
- upward release interval: **1500 ms**
- hold after loud event: **1000 ms**
- max normal downward step: **2 Media indexes**
- max upward step: **1 Media index**

**Strict**
- target loudness: **-18 LUFS-like**
- tolerance: **±1 LU**
- strength: **100%**
- normal downward attack: **50 ms**
- upward release interval: **1000 ms**
- hold after loud event: **800 ms**
- max normal downward step: **3 Media indexes**
- max upward step: **1 Media index**

**Off**
- no loudness-driven automatic raising;
- no loudness-driven automatic lowering except safety/transient/absolute max rules;
- Safety Lock and manual override remain active.

**Custom**
- sliders expose the same fields and start from the values of the preset from which Custom was entered.

## Advanced slider behaviour
Every slider row has:
- label + current numeric value;
- `?` help button;
- default value shown in help;
- safe experimentation guidance;
- `Reset` for that control where useful.

Opening Advanced does not silently alter saved settings. On first install the sliders exactly represent Medium/default-profile values. Selecting a built-in preset visibly moves the sliders to that preset. Editing any preset-controlled slider changes the selector to `Custom`.

Ship these read-only templates in addition to normalization presets:

The global defaults above.

- Safety Lock enabled at 40%;

- recovery interval 1000 ms.

### Stable loudness
- Maximum Media 60%;

### Movie / dynamic
- Maximum Media 70%;
- Light normalization;
- strong emergency/transient safety retained;

### Speech
- Maximum Media 60%;
- Medium normalization;
- target -19 LUFS-like;
- when verified multiband processing exists, prefer stronger dynamics on speech/mid bands; otherwise behave as ordinary Medium normalization.

Applying a built-in template copies it into an editable current profile. Users can save named custom profiles independently.

## Safety Lock final semantics
Safety Lock is an extra hard clamp after every other rule. It is useful even though Maximum Media already exists because Maximum Media is part of the normal operating profile while Safety Lock is the last independent invariant.

- App-originated writes are clamped before calling Android.
- Manual attempts above the lock are detected and clamped back at the first observable volume callback/poll.
- The app does not claim to disable the hardware key at OS level.
- A detected command/request above Safety Lock creates a red diagnostic entry even if the final guard successfully prevented the applied value.

## Diagnostics colours
Green means the subsystem is verified healthy now. Yellow means degraded/uncertain but safety fallback is active. Red means a definite fault or violated safety invariant.

The top card always contains:
- active backend tier;
- peak protection status;
- Manual Safety Pause state;
- Safety Lock state;
- log/anomaly detector state;
- current route;
- last measured reaction latency where available.

## Implementation acceptance additions
- Basic safety must be usable without MediaProjection when Visualizer(0) works on the device.
- AudioPlaybackCapture remains available as precision mode and fallback safety measurement.
- The first-block/raw detector and transient guard must have regression tests showing they do not wait for the 250 ms v0.3 RMS smoother.
- Device testing on SM-A528B must measure and display actual reaction latency for multiple sudden-level test cases.
