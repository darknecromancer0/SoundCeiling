# SoundCeiling v0.5.1 Core Stability Design

## Goal

Make the existing SoundCeiling core behave as an actual loudness normalizer/limiter on public Android APIs before adding large new features. This design is driven by the Samsung SM-A528B Android 34 field logs from 2026-08-21.

## Field-log findings

1. `transient_emergency` dominates the control loop because the transient baseline stops adapting whenever warning/emergency is active. A normal playback onset can therefore latch the guard indefinitely.
2. Every observed Hybrid Engine decision had `requested <= current`; no real normalization raise was requested. Mixed/global PCM was ACTIVE, but the confidence gate required EXACT source identity and PCM_EXACT before any automatic raise.
3. The raw peak guard compares the unattenuated source peak directly against the configured ceiling before deciding whether the already-attenuated output is unsafe. This can lower Media at index 1/2 even when `sourcePeak + streamGain` is far below the ceiling.
4. `ManualSafetyController` treats the initial volume at Minimum as an explicit manual pause. Automatic transient reductions also shrink the manual envelope. Both conflate user intent with algorithmic safety.
5. `Quiet now` computes an absolute quiet target and sends it through a clamp that can raise current volume to the configured quiet/safety index.
6. Apps & System Sounds synchronously enumerates installed packages on the UI thread every rebuild.
7. Simple UI and parts of Apps/System use hard-coded dark colors instead of the shared theme palette.
8. EQ lifetime is tied to the EQ screen, so changing tabs releases the effect. There is no persistent linked-band model.
9. Logging emits high-frequency `hybrid_control` rows even when nothing changes, causing 2 MiB part rotation and a confusing collection of files. `Open logs` launches a folder picker instead of opening a log browser.

## Control model

### A. Separate global PCM trust from per-app identity trust

Global normalization is allowed when all of the following are true:
- playback capture is healthy;
- PCM state is ACTIVE;
- metering is PCM_MIXED or PCM_EXACT;
- Media stream control exists;
- the resolved source set does not contain an explicit OFF conflict;
- normalization is enabled;
- no user/manual raise hold is active.

EXACT source identity is required only to apply identity-dependent per-app CUSTOM semantics or to claim PCM_EXACT. Unknown source with healthy ACTIVE mixed PCM uses the Global profile and is surfaced truthfully as `Global PCM / source unknown`.

Fallback/Visualizer/IDLE/SILENT/BLOCKED/UNCERTAIN states remain downward-only.

### B. Peak ceiling is an output ceiling

For source PCM peak `P` and current stream gain `G`, projected output peak is `P + G`. Emergency peak reduction happens only when projected output peak exceeds the configured dBFS ceiling. The safe gain limit is `ceiling - P`.

### C. Transient guard is edge-triggered, not a latch

The transient baseline must:
- reset/prime on signal start after silence;
- continue adapting during warnings/emergencies rather than freezing;
- use a short re-arm/cooldown so sustained loud content is not reported as a new transient every 10 ms;
- expose transitions for diagnostics but not flood the log.

Transient safety can request a downward move, but it must not mutate the user's manual envelope. Loudness hold/release already prevents an immediate rebound after a real automatic reduction.

### D. Manual intent is only manual intent

Initial observed Media volume establishes state without entering a manual pause. A later user decrease can temporarily block automatic raises and define a user ceiling. A user increase updates that ceiling. App-generated writes must never be fed back as user intent.

Minimum is only the lowest index the automatic controller may request. It is not an implicit `pause normalization` state.

### E. Quiet now is downward-only

`quietTarget = min(current, configuredQuiet, hardMax)` and the write path used by Quiet Now may never raise. It then creates an upward hold at the resulting volume without pretending an automatic safety reduction was a user slider move.

## Settings invariants

At every save and profile load:
- `minIndex <= maxIndex`;
- Safety Lock ceiling is inside `[minIndex, maxIndex]`;
- quiet target is inside the platform range, but Quiet Now still clamps downward from current;
- device/profile/media ceilings are monotonically combined by minimum;
- UI sliders dynamically prevent or correct impossible combinations instead of storing contradictory values.

## Diagnostics and logging

One service start to stop is one logical session ID. Physical part files, if required, share that session ID and are grouped in UI.

Default location: `Downloads/SoundCeilingLogs/` through MediaStore. A persisted SAF tree can be selected as an optional custom location. Settings show the active location and provide Choose folder and Default location actions.

`Open logs` opens an in-app Log Sessions screen, never the system folder picker. The screen groups rotated parts and supports open/share/delete for a logical session.

Control logging changes from frame spam to decision tracing:
- `volume_change`: current, requested, guarded/applied, direction, origin, reason, target loudness, measured loudness, raw/projected peak, PCM state, source confidence, policy mode, effective max, manual hold;
- `control_block`: transition-only reason when a desired raise/down action is blocked;
- `transient_transition`: NONE/WARNING/EMERGENCY transitions only;
- periodic compact `control_sample` at a low rate for context.

Retention is session-aware and bounded by count and byte budget.

## Apps & System Sounds

PackageManager enumeration and label resolution run on a background executor. The screen renders immediately with a loading placeholder and filters only an in-memory snapshot on the main thread. Runtime updates never re-enumerate packages.

## Theme

All screens use `UiTheme` palette helpers. No Simple-mode hard-coded black/white palette. Theme changes recreate the activity and all destinations receive the same theme.

## EQ

EQ configuration is independent from UI mode. Persist:
- enabled state;
- five band levels;
- selected link membership per band;
- Link Strength 0..100%.

Moving one linked band applies a proportional delta to other linked bands: `deltaOther = deltaMaster * strength`. Unlinked bands do not move. The EQ controller is not owned by `EqView`; leaving the tab does not release the effect while the process/service owns it. Safety control remains independent if EQ is unavailable.

## UI language

- Advanced reset button: `По умолчанию`.
- Behavior adds `Custom` state when individual timing/step settings no longer match a named speed preset.
- Help uses plain-language explanations for PCM, DSP, Peak, RMS, dBFS, dB SPL, LUFS and LUFS-like. LUFS-like is explicitly described as an approximate loudness estimate, not standards-compliant integrated LUFS.
- Calibration copy states clearly that it is only required for dB SPL estimates; normal dBFS/LUFS-like operation does not require calibration.
- Advanced places runtime/control status and primary loudness/limits before secondary timing knobs.

## Release gates

v0.5.1 must prove:
1. quiet PCM can request upward normalization under Global ACTIVE PCM without exact source;
2. target changes change the requested direction/target;
3. loud PCM requests downward normalization;
4. peak ceiling evaluates projected output peak;
5. transient onset does not latch emergency;
6. initial Minimum does not disable raising;
7. Quiet Now never raises;
8. app-generated writes do not become user overrides;
9. invalid range combinations are normalized;
10. package enumeration is absent from synchronous AppsSystemView rebuild path;
11. theme contract covers Simple and Apps/System;
12. EQ link math is pure-tested and EQ state is not tied to view detach;
13. log UI/location/session grouping contracts pass;
14. all existing v0.4/v0.5 safety, microphone-isolation, package and release tests remain green;
15. `:app:assembleDebug` succeeds and the APK checksum is published.
