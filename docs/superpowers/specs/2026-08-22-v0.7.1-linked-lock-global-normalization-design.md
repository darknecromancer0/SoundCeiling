# SoundCeiling v0.7.1 · Linked Lock и глобальная нормализация

**Статус:** дизайн одобрен в чате 2026-08-22; реализация заблокирована до просмотра этой письменной спецификации.

**Ветка:** feature/v0.7-adaptive-envelope, продолжение draft PR #8.

**Основная цель:** максимально приблизить весь доступный выходящий звук к одной выбранной воспринимаемой громкости. Крик, музыка, речь и шёпот должны выходить из текущего динамика или наушников с близким уровнем без быстрых скачков, постоянного движения системного ползунка и ложных аварийных снижений.

## 1. Основание для переработки

Шесть Samsung SM-A528B Android 34 логов v0.7.0 показывают архитектурную регрессию:

- в последней сессии контроллер почти после каждого изменения меняет направление 4→3→4, иногда через 38–202 мс;
- quiet_now_hold занимает 53 889 из 57 779 строк, потому что обычный HOLD ошибочно определяется как Quiet Now;
- источник остаётся UNKNOWN во всех сессиях;
- PCM ACTIVE и SILENT_SOURCE могут переключаться по одному 10-мс блоку;
- относительный transient вызывает снижение даже при безопасном projected peak;
- B1 fallback не рассчитывает частотные полосы, поэтому визуализатор выглядит сломанным;
- текущий Adaptive Envelope разрешает UP только как возврат собственного прежнего снижения и поэтому не умеет полноценно усиливать изначально тихий материал;
- Samsung сообщает кривую громкости в значениях, похожих на линейные коэффициенты 0…1, но текущий валидатор принимает их как dB, а контроллер использует отдельную синтетическую кривую;
- Target имеет 101 положение, хотя STREAM_MEDIA предоставляет только 15 аппаратных ступеней, некоторые из которых на этом устройстве отличаются примерно на 5 dB.

Текущие source-contract тесты проходят, но не воспроизводят временную динамику полевого контура.

## 2. Главный пользовательский контракт

SoundCeiling стремится удерживать доступный выходной звук около выбранного выходного уровня.

- звук выше верхней границы ослабляется;
- звук ниже нижней границы усиливается;
- звук внутри разрешённого диапазона не требует коррекции;
- в Default Linked Lock нижняя и верхняя границы совпадают с одной желаемой точкой;
- внутренняя стабилизационная зона, soft knee и hysteresis не меняют показанные связанные значения и существуют только для устранения дрожания;
- системный ползунок Samsung является пользовательским мастер-регулятором желаемого результата;
- автоматические Media writes SoundCeiling являются исполнительными действиями и не изменяют пользовательскую желаемую точку;
- ручное изменение Samsung Media изменяет желаемую точку или сдвигает пользовательский диапазон;
- Safety Maximum и явные политики приложений/потоков всегда имеют приоритет.

Результат оценивается по выходной воспринимаемой громкости, а не по тому, находится ли Samsung Media на одном и том же индексе.

## 3. Термины и независимые величины

Спецификация разделяет:

- **Desired Output Level** — выбранная пользователем желаемая выходная громкость;
- **Lower Output Ceiling** — уровень, ниже которого normalizer пытается усилить материал;
- **Upper Output Ceiling** — уровень, выше которого normalizer пытается ослабить материал;
- **Media Actuator Range** — разрешённый диапазон аппаратных Samsung Media индексов;
- **Safety Maximum** — абсолютный верхний аппаратный предел;
- **DSP Gain** — непрерывная прибавка или ослабление в обрабатываемом аудиотракте;
- **Raw Peak** — краткий PCM peak до доказанного выходного gain;
- **Projected Peak** — оценка peak после применимого Media/DSP gain;
- **Verified Output Loudness** — подтверждённая или лучшая доступная оценка сигнала после обработки;
- **LUFS-like** — realtime оценка воспринимаемой громкости, а не сертифицированный integrated LUFS;
- **Calibrated dB SPL** — приблизительный физический уровень только для калиброванного output route.

Без SPL-калибровки приложение может выравнивать относительную выходную громкость, но не должно называть её точным физическим dB SPL.

## 4. Capability ladder: лучший доступный тракт

Движок выбирает наиболее качественный разрешённый и доказанный тракт для текущего route и активного набора источников.

### 4.1 Verified Policy-Scoped DSP

Предпочтительный режим. Непрерывный compressor/gain controller подключается только к разрешённым audio sessions, для которых SoundCeiling получил session handle через документированный доверенный API и может связать handle с политикой. Человекочитаемое имя YouTube, Яндекс Музыки или другого приложения не обязательно, если происхождение handle и разрешённый usage доказаны.

Стандартный публичный `AudioPlaybackConfiguration` на поддерживаемых версиях Android предоставляет `AudioAttributes`, но не предоставляет стороннему приложению публичные `getAudioSessionId()` или `getClientUid()`. Поэтому v0.7.1 не извлекает эти данные рефлексией, перебором session ID или скрытыми API и не заявляет policy-scoped DSP для чужого playback без отдельного документированного handle. Источник: [Android AudioPlaybackConfiguration](https://developer.android.com/reference/android/media/AudioPlaybackConfiguration).

Он используется только когда:

- Android/OEM позволил создать эффект;
- проверка доказала измеримое влияние на предназначенные sessions при неизменном Media index;
- текущие политики приложений и системных потоков допускают обработку;
- watchdog не обнаружил потерю или обход DSP transport;
- route не изменился после последней действительной проверки.

Такой тракт позволяет одновременно нормализовать несколько разрешённых источников и оставить OFF source без эффекта.

### 4.2 Verified Global-Mix DSP

Эффект на общем output mix даёт самое широкое покрытие, но применяется только если scope probe доказал, что он не затрагивает default-OFF system usages, либо пользователь явно разрешил все usages, которые этот transport изменяет.

Если scope общего эффекта включает запрещённые звонки, будильники, уведомления, system UI или OFF packages, такой transport не считается policy-compatible и не активируется. Простого отсутствия системного звука в момент запуска недостаточно: новый notification не должен попасть под уже работающий общий эффект до callback.

MediaSession-кандидат сам по себе не считается доказательством доступа к DSP.

### 4.3 Stable Media AGC fallback

Если сам сигнал изменить нельзя, SoundCeiling использует измеритель, исправленную route curve и дискретный STREAM_MEDIA actuator. Этот режим должен быть стабильным и честно обозначаться как ступенчатый fallback, а не DSP.

### 4.4 Safety-only fallback

Если достоверного loudness meter нет, сохраняются только доказанные hard ceilings и безопасные downward-only реакции на реально доступные данные. Неизмеряемый звук не получает выдуманные LUFS/dB значения.

### 4.5 Исполнимая граница v0.7.1 на stock Android

`DynamicsProcessing` документированно присоединяется к заданному audio session ID; наличие эффекта не даёт SoundCeiling права узнать session ID чужого проигрывателя. Источник: [Android DynamicsProcessing](https://developer.android.com/reference/android/media/audiofx/DynamicsProcessing).

Поэтому порядок для YouTube, Яндекс Музыки и другого стороннего playback на обычном непривилегированном Android такой:

1. использовать Verified Policy-Scoped DSP только при наличии документированного доверенного session handle;
2. использовать Verified Global-Mix DSP только если эффект доказан на текущем route и пользователь явно разрешил всю область, которую нельзя безопасно разделить по app/usage, либо OEM предоставляет доказательство более узкого scope;
3. во всех остальных случаях использовать Stable Media AGC fallback;
4. не выдавать Media fallback за непрерывный DSP и прямо показывать ограничение аппаратной ступенью.

Shizuku/root, hidden API и перебор session ID не входят в v0.7.1. Такой transport можно проектировать отдельно только после явного согласия пользователя на привилегированный режим.

## 5. DSP используется глобально, но учитывает политики приложений

Определение источника не является условием обычного включения глобального DSP. Оно необходимо для исключений, per-app профилей и конфликтов одновременно звучащих источников.

### 5.1 Значения по умолчанию

- обычные сторонние приложения наследуют Global и допускают нормализацию;
- системные, Samsung и Android packages по умолчанию имеют OFF;
- из системных streams по умолчанию включён только MEDIA;
- CALLS, ALARM, RINGTONE, NOTIFICATIONS, SYSTEM, DTMF, ACCESSIBILITY и ASSISTANT по умолчанию не управляются;
- пользователь может явно включить конкретное системное приложение или stream во вкладке «Приложения и системные звуки».

Это сохраняет контракт предыдущих версий: установка SoundCeiling не должна неожиданно менять звонки, будильники, уведомления, интерфейсные щелчки, accessibility или другие системные приложения.

### 5.2 Policy-aware arbitration

DSP на общем mix физически не может одновременно изменить разрешённый source и не изменить запрещённый source, если они уже смешаны. Поэтому:

- policy-scoped effects создаются только для разрешённых sessions/usages;
- global-mix transport не активируется вообще, если его проверенный scope способен затронуть хотя бы один неразрешённый system usage;
- пользователь может сделать global-mix transport допустимым, явно включив соответствующие system streams;
- если scope transport изменился или стал неопределённым, DSP плавно возвращается в neutral и verification отзывается;
- после безопасного устранения конфликта normalizer возвращается через warmup, без резкого gain snap;
- при неизвестном package используются только реально доступные public usage evidence и отдельно помеченные MediaSession candidates; они не превращаются в доказанную связь package↔player;
- системные AudioAttributes usages блокируют глобальную обработку по умолчанию даже без имени package;
- если нет trusted handle и usage/source evidence не позволяют проверить policy, непрерывный UP/DSP для этого source блокируется и выбирается безопасный fallback;
- UNKNOWN не может активировать индивидуальный CUSTOM профиль или отменить явный системный OFF.

Multi-source policy использует самый строгий запрет и самые строгие safety limits.

### 5.3 Ограничения платформы

Телефонные разговоры, защищённый audio, hardware/offload paths или OEM-тракты могут быть недоступны public Android API. UI сообщает точную причину недоступности. Приложение не заявляет универсальную обработку там, где она не доказана.

## 6. Проверка DSP и runtime truth

Существование Android Equalizer или DynamicsProcessing object не является доказательством обработки.

Состояния транспорта:

- UNAVAILABLE;
- PROBE_REQUIRED;
- PROBING;
- VERIFIED_POLICY_SCOPED;
- VERIFIED_GLOBAL_MIX;
- BYPASSED_BY_POLICY;
- LOST_VERIFICATION;
- FAILED.

Проверка должна:

1. сохранить текущие Media, route и настройки;
2. использовать небольшой ограниченный DSP gain change без Media write;
3. сравнить доступную pre/post или независимую output-mix оценку;
4. подтвердить ожидаемое изменение с заданной погрешностью;
5. восстановить neutral gain в любом success/error/cancel пути;
6. сохранить результат с привязкой к manufacturer/model/SDK/route и типу транспорта;
7. для global-mix отдельно сохранить доказанный набор затрагиваемых usages/scopes;
8. сбросить подтверждение при route change, effect error, session replacement или несовместимом offload transition.

Для проверки third-party global path app-owned tone недостаточен сам по себе. Если нельзя независимо доказать влияние на текущий внешний playback, состояние остаётся PROBE_REQUIRED или UNAVAILABLE.

RuntimeState, логи и UI отдельно показывают:

- анализ PCM;
- активность EQ;
- DSP transport;
- policy bypass;
- фактический actuator.

## 7. Default Linked Lock в простом режиме

Default Linked Lock включён при первой установке и после явного применения default preset.

### 7.1 Включённое состояние

- Lower Output Ceiling равен Upper Output Ceiling;
- начальная точка соответствует Target 50%, то есть около −20 LUFS-like в некалиброванной digital scale;
- correction goal равен 100%, но attack, release, soft knee, gain slew и hysteresis ограничивают скорость, а не оставляют постоянные 20% ошибки;
- auto-mute выключен;
- ручное движение Samsung Media сдвигает связанную точку по route curve;
- app-owned Media writes не сдвигают точку;
- Ceilings, Target/Normalization и остальные параметры, определяемые default preset, остаются видимыми, обновляются, но серые и недоступные;
- возле disabled controls показывается «Управляется Default Linked Lock»;
- Safety Maximum остаётся самостоятельным доступным safety control;
- Start/Stop остаётся доступным;
- Quiet Now отсутствует в простом режиме.

Визуально disabled controls используют theme-aware disabled alpha/цвет и сохраняют читаемый контраст.

### 7.2 Выключение

Выключение Linked Lock не меняет звук и значения в момент переключения:

- оба Ceilings остаются равными текущей связанной точке;
- controls становятся активными без rebuild flicker;
- пользователь может раздвинуть Lower и Upper;
- invariant Lower <= Upper применяется при каждом изменении;
- Target становится производной выбранного диапазона, а не конкурирующей третьей целью;
- параметры normalizer становятся редактируемыми в пределах стабильных safety constraints.

### 7.3 Ручной Samsung slider при выключенном Linked Lock

Ручное изменение Media сдвигает оба Output Ceilings на один и тот же route-curve delta и сохраняет расстояние между ними.

Пример:

- Linked: 50–50;
- пользователь выключает Linked: остаётся 50–50;
- пользователь выставляет 45–55;
- ручное повышение Samsung на эквивалент +10 сдвигает диапазон к 55–65.

Clamping у границы шкалы сначала сохраняет ширину диапазона, насколько возможно. Если вся ширина физически не помещается, ближайшая граница ограничивается и UI показывает это явно.

### 7.4 Provenance

VolumeWriteTracker обязан различать:

- USER_CHANGE — изменяет связанную точку или сдвигает unlocked диапазон;
- APP_WRITE_ACK — не меняет пользовательские output ceilings;
- APP_WRITE_STALE/MISMATCH — приостанавливает автоматическое UP и не создаёт пользовательский target;
- HARD_CAP — не меняет target;
- ROUTE_EXTERNAL — сбрасывает старую curve authority и требует rebase.

## 8. UI простого и расширенного режимов

Обязательные названия:

- «Простой режим» вместо «Основные»/«Основное»;
- «Расширенный режим» вместо «Расширенные».

Простой режим содержит:

- status card с текущим режимом DSP/fallback;
- Default Linked Lock;
- Lower Output Ceiling;
- Upper Output Ceiling;
- Target/Normalization status;
- Safety Maximum;
- основной Start/Stop;
- краткое сообщение, охвачен ли текущий output и не блокирует ли его app/system policy.

При Linked Lock часть controls disabled, но их текущие значения остаются видимыми.

Расширенный режим дополнительно содержит:

- Media actuator min/max;
- soft-knee/tolerance;
- attack/release/hold;
- gain/write slew;
- max Media steps;
- peak/transient protection;
- DSP verification state;
- source/multi-source evidence;
- calibrated SPL;
- отдельные app/system policy причины.

Строка auto-mute разделяется на короткий заголовок «Разрешить автоматический mute» и подпись «Нулевая ступень Media (0)». Никакой фиксированный parent height не может обрезать подпись.

Блок «Шкала управления» использует vertical/wrapping layout. Help button закреплён сверху, а высота текста измеряется содержимым.

## 9. Единая route volume curve

Текущая синтетическая ControlVolumeCurve больше не может быть независимым источником истины.

Route curve pipeline:

1. получить vendor values для всех Media indices;
2. классифицировать единицы:
   - линейные amplitude/gain 0…1 преобразовать через 20 log10;
   - монотонные dB <= 0 использовать как dB;
   - −Infinity трактовать как mute floor;
   - невалидные/плоские/немонотонные данные отклонить;
3. сохранить normalized dB curve и причину выбора;
4. использовать её для actuator mapping, manual delta, projected output и UI;
5. fallback curve использовать только с явным diagnostics marker.

Для Samsung field fixture ожидается приблизительная normalized curve:

−80, −53, −48, −43, −38, −33, −28, −23, −21, −19, −16.5, −14, −11, −8, −4.5, 0 dB.

Контроллер обязан определить, является playback PCM pre-volume или post-volume. Если PCM уже изменяется вместе с Media, Media gain нельзя прибавлять повторно. Режим определяется controlled route probe и хранится как PRE_VOLUME, POST_VOLUME или UNKNOWN. UNKNOWN выбирает консервативный расчёт и блокирует агрессивный UP.

## 10. Stable Media AGC fallback

STREAM_MEDIA остаётся дискретным actuator и не должен имитировать sample-level DSP.

Обязательные свойства:

- asymmetric program envelope: быстрый rise для громкого материала, медленный fall/release для коротких ям;
- activity gate с onset confirmation и silence hangover;
- Schmitt-style decision thresholds;
- отдельный minimum direction dwell;
- обычное изменение не более одной Samsung ступени за write;
- emergency multi-step разрешён только при подтверждённо опасном absolute projected output;
- ordinary DOWN для устойчиво громкого материала начинается не позднее 500 мс;
- recovery не реагирует на короткую паузу и выполняется ступенчато;
- no UP/DOWN reversal быстрее одной секунды, кроме доказанного нового absolute safety violation;
- пользовательские значения Advanced нормализуются через safety floors и не могут выставить attack 0, hold 68 мс и release 100 мс в комбинации, создающей осциллятор;
- UI показывает фактический Samsung index и percent для обеих аппаратных границ.

Target percent остаётся удобной шкалой желаемого output, но UI не обещает 101 уникальный аппаратный результат. В fallback отображается ближайший эффективный диапазон/ступень.

## 11. Loudness, peak и transient

### Loudness envelope

Control loudness и display LUFS-like разделены:

- control path использует bounded fast attack, slow release и program activity;
- display path остаётся более медленным и визуально стабильным;
- краткая тишина не создаёт немедленный boost;
- sustained whisper может получать UP, если политика и actuator позволяют;
- sustained scream получает DOWN или DSP attenuation.

### Peak safety

Peak emergency оценивает ожидаемый выход:

projected peak = raw peak + доказанный применимый Media/DSP gain.

Raw peak выше порога сам по себе не снижает Media, если projected output уже безопасен.

### Transient

Delta transient:

- не срабатывает на первом block после тишины/route/source transition;
- требует continuous activity и confirmation;
- не выполняет emergency down при безопасном absolute projected output;
- обновляет baseline во время устойчивого нового уровня;
- пишет лог только при смене состояния;
- transient safety не изменяет пользовательские ceilings.

## 12. PCM state и источник

PcmAvailabilityState использует stateful resolver:

- ACTIVE требует подтверждённого сигнала;
- короткая яма остаётся ACTIVE через hangover;
- SILENT_SOURCE требует устойчивой тишины;
- новый ACTIVE получает meter/transient warmup;
- STARTING/BLOCKED/UNCERTAIN не создают выдуманную loudness authority.

Source UX показывает раздельно, без ложной корреляции:

- Notification/MediaSession access granted/connected;
- активные public usage candidates;
- package candidates из MediaSession/Notification Listener;
- trusted session handles только когда их дал документированный provider;
- targeted или mixed PCM;
- финальную confidence;
- app/system policy;
- причину global DSP bypass.

Кнопка «Разрешить определение источника» открывает Android Notification Listener settings.

Если candidate появляется или меняется во время работы, capture coordinator безопасно переоткрывает targeted/mixed capture без полного перезапуска приложения, применяет warmup и сохраняет пользовательские ceilings.

YouTube и Яндекс Музыка могут оставаться LIKELY/MIXED, если Android запрещает targeted PCM. Это не блокирует policy-compatible Global DSP или Global PCM normalization.

## 13. Frequency visualizer

Precise PCM вычисляет полосы из PCM как сейчас.

B1 Visualizer fallback:

- использует доступный waveform/FFT, если Android его предоставляет;
- normalizes bands отдельным fallback tracker;
- сообщает measurement age;
- если waveform/FFT недоступен, показывает «Спектр недоступен в текущем fallback», а не нулевой рабочий график;
- смена B2↔B1 очищает stale bands и публикует явный backend transition.

Speaker check и calibration state machine после завершения возвращают прежний precise mode, если MediaProjection остаётся действительным; они не должны незаметно оставлять приложение в B1.

## 14. Apps & System Sounds

Вкладка остаётся источником пользовательского согласия для исключений:

- GLOBAL — наследует global normalizer;
- ON — явно разрешает обработку;
- OFF — запрещает DSP и Media control для этого source;
- CUSTOM — задаёт собственные ceilings/strength/DSP preference;
- DSP AUTO — лучший verified transport;
- DSP PREFER — предпочесть DSP, но не выдавать unverified за working;
- DSP DISABLE — запрет DSP для source.

System streams показывают enabled и ceiling. Defaults включают только MEDIA.

Отдельное согласие «Global DSP для всей неделимой области выхода» по умолчанию OFF и находится только во вкладке приложений/системных звуков или в расширенном режиме. Его включение требует предупреждения, что эффект может изменить notifications, alarms, calls и system UI sounds. Это согласие не выводится из старого DSP AUTO/PREFER и не включается миграцией.

При одновременном playback:

- любой OFF source блокирует общий DSP mix;
- отдельные разрешённые verified source effects могут продолжить работу;
- общий STREAM_MEDIA write не выполняется, если он изменит OFF source;
- UI показывает конфликтующие packages/usages.

## 18. Ошибки и fail-safe

- DSP create/configure/probe error немедленно возвращает neutral и выбирает следующий capability tier;
- policy ambiguity блокирует policy-scoped/global-mix DSP и automatic UP, но не отключает доказанный safety limit;
- route change сбрасывает DSP verification, transient state и capture reference mode;
- stale/mismatched Media provenance блокирует UP до reconciliation;
- unavailable meter не создаёт gain request;
- app/system OFF всегда сильнее global normalization;
- service stop восстанавливает neutral DSP и освобождает effects;
- crash recovery при следующем старте сначала принудительно устанавливает neutral configuration;
- настройки не могут сохранить Lower > Upper или Safety Maximum вне аппаратного диапазона.

## 20. Release acceptance

### Verified DSP

- a program loudness jump of at least 20 dB settles near Linked target without moving Samsung Media back and forth;
- after settling, output remains within approximately ±1.5 loudness units when meter and transport support that precision;
- gain reduction begins no later than 100 ms and settles within 500 ms for a sustained loud level;
- upward correction starts only after at least 300 ms of confirmed quiet program and settles within 1 s without overshoot;
- app/system OFF sources remain unaffected.

### Media fallback

- no opposite-direction Media write within 1 s except a new absolute safety violation;
- ordinary writes are one step;
- sustained loud correction begins within 500 ms;
- settled error is bounded by one hardware step plus meter tolerance;
- UI states that exact continuous equality is unavailable in fallback.

### Overall

- user can hear a clear difference between SoundCeiling ON and OFF on alternating scream/whisper material;
- человекочитаемое имя source не требуется, но доступных usage/policy evidence должно хватать для выбранного actuator; MediaSession package candidate сам по себе не доказывает соответствие конкретному player;
- system apps/streams remain opt-in;
- Target and Ceilings behave monotonically and their effective actuator resolution is visible;
- no quiet_now log flood;
- no first-run frequency visualizer failure without an explicit unavailable status;
- no clipped text from the supplied screenshot scenarios.
