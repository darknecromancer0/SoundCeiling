# SoundCeiling v0.7 Adaptive Envelope Design

**Status:** Architecture approved in chat. Implementation remains blocked until this written spec is reviewed.

**Base:** `main` at SoundCeiling v0.6.0 (`e9c6f75333f133bc4fdf82d9cb95c4e3f3b91942`).

**Goal:** Replace v0.6 global one-way HOLD/DOWN semantics with a user-authoritative adaptive envelope: SoundCeiling may automatically recover from its own reductions, but it must never fight a deliberate manual Samsung Media reduction. At the same time v0.7 fixes transient overreaction, source/DSP truthfulness, Logs indexing, clipped UI text, light-theme meter contrast, and missing EQ visualization/amount controls.

## 1. Evidence from the v0.6 field test

The v0.7 design is grounded in the user's Samsung SM-A528B test and the two v0.6 logs collected on 2026-08-22.

Observed behavior that must be addressed:

- `TRANSIENT_EMERGENCY` can reduce Media by several Samsung indices at once, including `4 -> 1` and `2 -> 1`.
- ordinary loudness normalization also performs abrupt reductions such as `5 -> 3`.
- after an automatic reduction, v0.6 has no upward recovery path because `LoudnessControlPolicy` clamps every ordinary result to `<= currentIndex`.
- manual slider movement is already observed and converted to a dB offset, but that offset only changes thresholds; it cannot restore Media after SoundCeiling itself reduced it.
- hard-cap clamping is fast but necessarily reactive: Android may visually expose one forbidden Samsung step before SoundCeiling writes the allowed value back.
- source identity remains `UNKNOWN` and PCM remains mixed because optional MediaSession evidence is not surfaced as an explicit onboarding requirement.
- DSP status remains `UNAVAILABLE` because the current optional DSP controller is deliberately fail-closed and never verifies a global/source transport.
- log files are successfully written to `Downloads/SoundCeilingLogs`, but the in-app Sessions screen can still show an empty list because it re-discovers files through MediaStore/SAF rather than keeping a durable index of successfully created parts.
- the frequency meter uses hard-coded colors and therefore has excessive contrast/poor label readability in the light theme.
- long slider labels can wrap into content below them and visually clip glyphs.
- the EQ screen has band controls but no live spectrum, no correction-curve visualization, and no independent global EQ amount control.

## 2. Non-negotiable control rule

The primary v0.7 contract is:

> **After an automatic SoundCeiling reduction, SoundCeiling may gradually restore Media. After a deliberate manual Media reduction, the user's new Media position becomes an automation ceiling. SoundCeiling may not automatically exceed that user ceiling until the user raises Media again.**

This rule overrides the v0.6 global one-way rule.

Consequences:

1. Automatic DOWN and automatic RECOVERY are both valid controller actions.
2. Manual DOWN is never interpreted as a temporary disturbance to be corrected.
3. Manual UP explicitly widens the current user envelope, up to configured Maximum/Safety Lock.
4. Automatic recovery may restore only reductions attributable to SoundCeiling, not reductions attributable to the user.
5. Configured Maximum and Safety Lock remain absolute upper bounds regardless of user envelope.
6. The user may still force Media lower than Minimum; SoundCeiling does not fight that action.

## 3. Separate the three ceilings

v0.7 must stop overloading one index as several different concepts.

### 3.1 Configured maximum

The user's persistent SoundCeiling `Maximum` setting. This is the long-term ceiling configured in Main/Advanced.

### 3.2 User envelope ceiling

The highest Media index SoundCeiling is currently allowed to select automatically.

- initialized from the current Media position, capped by configured Maximum/Safety Lock;
- moves immediately or near-immediately downward when the user deliberately lowers Media;
- expands when the user deliberately raises Media;
- is never increased by an application write acknowledgement;
- persists only as runtime/user-intent state unless later testing demonstrates that persistence across process death is desirable.

### 3.3 Safety ceiling

The strictest absolute ceiling from configured Maximum, Safety Lock, device policy and any stronger explicit safety constraint.

The executor always enforces:

`automaticTarget <= userEnvelopeCeiling <= safetyCeiling`

When the user directly requests a position above `safetyCeiling`, SoundCeiling may clamp it back because that is an explicitly configured hard cap.

## 4. Volume provenance and authority

`VolumeWriteTracker`/volume observation becomes the source of truth for who moved Media.

Every observed index transition must resolve to one of at least:

- `USER_CHANGE`
- `APP_WRITE_ACK`
- `APP_WRITE_MISMATCH`
- `UNKNOWN_EXTERNAL`

The adaptive envelope changes only from deliberate/manual/external user-intent evidence, never from an acknowledged SoundCeiling write.

### Manual DOWN

Example: user moves Samsung `8 -> 5`.

- set user envelope ceiling to at most `5` immediately;
- shift effective normalization/safety thresholds downward using the volume curve;
- cancel any pending upward recovery that would exceed 5;
- SoundCeiling may still automatically reduce below 5 when the content is too loud.

### Manual UP

Example: user moves `5 -> 7`.

- user envelope ceiling widens to at most 7;
- threshold offset restores smoothly rather than snapping;
- automatic recovery may subsequently move an automatically attenuated value upward, but never above 7.

### SoundCeiling automatic DOWN

Example: controller writes `7 -> 5`.

- user envelope remains 7;
- controller records an automatic attenuation debt of approximately the curve delta between 7 and 5;
- when content becomes too quiet relative to target and all safety conditions are satisfied, the debt may be repaid gradually by automatic recovery toward 7.

## 5. Adaptive-envelope state model

Introduce a pure state component, tentatively `UserVolumeEnvelope` or `AdaptiveVolumeEnvelope`, responsible only for intent/accounting. It must perform no Android writes.

Minimum state:

- `userCeilingIndex`
- `lastObservedIndex`
- `automaticReferenceIndex` / recoverable automatic attenuation
- manual threshold offset dB
- `lastManualChangeAtMs`
- `lastAutomaticDownAtMs`
- `lastAutomaticUpAtMs`
- recovery hold/release state

Required pure operations:

- observe initial state;
- observe manual down;
- observe manual up;
- observe app-write acknowledgement;
- compute effective automatic min/max bounds;
- compute recoverable-up limit;
- reset/repair state after ambiguous provenance or route change.

Ambiguous provenance must fail conservative: it may lower the automation ceiling, but must never grant new upward authority.

## 6. Bidirectional loudness controller inside the envelope

`LoudnessControlPolicy` changes from one-way to envelope-bounded bidirectional normalization.

Controller outcomes:

- `HOLD`
- `DOWN`
- `RECOVER_UP`

`RECOVER_UP` is not generic volume boosting. It is repayment of previously automatic attenuation and is capped by the current user envelope.

### DOWN

When effective output loudness is above target + tolerance:

- calculate desired gain through the existing dB curve/GainPlanner;
- apply normalization strength;
- respect downward attack;
- rate-limit by `maxDownSteps`;
- treat configured Minimum as the floor for **automatic attenuation only**;
- if the user has manually placed Media below Minimum, HOLD rather than raising merely to satisfy Minimum;
- respect auto-mute policy;
- never exceed effective safety/user ceilings.

### RECOVER_UP

When effective output loudness is below target - tolerance:

- recovery is allowed only if current index is below the recoverable automatic reference/user envelope;
- wait through a `holdAfterLoudMs` interval after meaningful loud/transient/peak activity;
- use `upwardReleaseMs` and `maxUpSteps` to make recovery deliberately slower than emergency attenuation;
- stop at `min(userEnvelopeCeiling, safetyCeiling, recoverableReference)`;
- if the user manually lowered Media, recovery ceiling collapses with the user's action and must not fight it;
- no upward move is authorized merely because content is quiet; a known recoverable automatic attenuation must exist.

### HOLD

Within tolerance, during holds, during uncertain provenance, when the user is below configured Minimum, or when no recoverable attenuation exists.

## 7. Defaults and profiles

v0.7 restores upward timing fields as active behavior rather than legacy serialized fields.

Profiles expose:

- Target loudness
- Normalization strength
- Tolerance
- Downward attack
- Max down steps
- Hold after loud
- Upward release
- Max up steps

Recommended defaults should favor smoothness:

- automatic ordinary down: small steps;
- automatic ordinary up: one Samsung step at a time by default;
- upward release slower than downward correction;
- emergency protection remains faster than both.

Exact preset values are implementation/test-plan decisions, not hard-coded by this design spec.

## 8. Transient Guard 2.0

The current fast baseline can classify a normal start/re-entry as a huge transient after very quiet material. v0.7 must distinguish an actual dangerous transient from playback onset/restart.

### Required behavior

1. **Playback-onset warmup:** after `IDLE/SILENT_SOURCE -> ACTIVE`, transient delta is diagnostic only for a short bounded warmup, approximately 200-300 ms.
2. **Baseline priming:** the first trustworthy active blocks prime the transient baseline rather than causing an emergency.
3. **Persistence:** ordinary delta-based emergency requires persistence across multiple blocks or a short confirmation interval.
4. **Absolute escape hatch:** an absolute peak/projected-peak violation may still trigger immediate protection without waiting for persistence.
5. **Rate limiting:** delta-based transient attenuation should normally be limited to a small number of Samsung indices per decision rather than collapsing `4 -> 1` in one write.
6. **Re-evaluation:** if the dangerous condition persists, subsequent decisions may continue downward until safe.
7. **Recovery:** transient-induced attenuation becomes recoverable automatic attenuation once the hold/release conditions are satisfied.

Pure tests must include playback onset, silence-to-music, real peak emergency, repeated transient emergency, and post-emergency recovery.

## 9. Hard cap behavior on stock Android

v0.7 must be explicit about what is and is not possible.

On stock Android/Samsung without privileged APIs, SoundCeiling cannot change the physical range of the Samsung volume UI before the system processes the user's press. Therefore a forbidden visual step may appear very briefly.

What v0.7 guarantees instead:

- observation loop remains fast;
- values above configured Safety/Maximum are clamped back immediately through the established safe write path;
- app-write acknowledgement prevents feedback loops;
- UI/diagnostics call this `hard cap clamp`, not a claim that the Samsung slider itself has been reconfigured.

Future root/Shizuku/OEM system-volume-range control remains out of scope for Standard v0.7.

## 10. Control scale in Advanced

Add an explicit control-scale selector rather than mixing units implicitly.

### `Media %`

- Minimum/Maximum expressed primarily as Samsung Media position/percentage;
- Target loudness remains available as normalization behavior;
- this is the default/simple mental model.

### `Digital dB`

- exposes Target LUFS-like, tolerance, Projected Peak dBFS and related digital-domain controls as the primary surface;
- Media indices remain the actuator, chosen from the calibrated/estimated volume curve inside the user envelope;
- must label values as digital estimates, never physical room loudness.

### `Calibrated dB SPL`

- available only for a calibrated current output route;
- uses the existing calibration/profile path;
- clearly marked approximate;
- if calibration is absent, the mode cannot silently turn itself on.

The three modes share the same engine; they change the UI/configuration projection, not the fundamental safety path.

## 11. Main screen cleanup

Required changes:

- remove `только вниз` from Normalization;
- update intro copy from global one-way wording to adaptive-envelope wording;
- display Minimum both as index and percentage where meaningful, e.g. `1/15 · 7%`;
- retain Maximum percentage;
- preserve Target and Quiet Now help affordances;
- make all dynamic labels multi-line safe with adequate measured height and bottom spacing;
- no fixed-height parent may clip a wrapped label.

The Main screen should explain the rule in one sentence: SoundCeiling can restore its own attenuation but never raises above the user's current envelope.

## 12. Advanced screen cleanup

Rename `Поведение · только снижение` to `Динамика нормализации`.

Expose:

- speed preset;
- downward attack;
- max down steps;
- hold after loud;
- upward release;
- max up steps;
- auto-mute;
- control scale selector;
- explicit live `User ceiling`, `Safety ceiling`, `Automatic reference`, `Effective Target`, `Auto attenuation`, `Recovery allowed/blocked reason`.

The purpose is that one screenshot/log can explain why volume moved.

## 13. Frequency meter and light theme

`FrequencyMeterView` must stop using hard-coded `Color.LTGRAY`, dark RGB backgrounds and saturated green independent of theme.

Use semantic theme colors for:

- meter track/surface;
- live fill;
- labels;
- optional grid/reference line.

Light theme target:

- low-contrast neutral track;
- readable secondary labels;
- moderate accent fill rather than dark slabs on white;
- dark theme remains legible without separate widget-specific hard-coded palettes.

Labels must not visually disappear when the band level is zero.

## 14. EQ v0.7 visualization and amount

EQ remains an independent application-owned module, but the screen gains missing feedback.

### Live spectrum

Reuse the same five-band runtime spectrum already available to Advanced, or a shared visualizer component, so the EQ page shows live input energy per Bass/Low/Mid/Presence/Air region.

If no trustworthy spectrum is available, render an explicit inactive/awaiting state rather than fake motion.

### EQ correction curve

Render a lightweight curve/area plot representing the configured band gains. This is a UI visualization of settings, not a claim of measured acoustic output.

### EQ Amount

Add `EQ Amount` / `Сила EQ` 0-100%.

Semantics:

`effectiveBandGain = configuredBandGain * amount`

This is independent of `Link Strength`.

- `Link Strength` controls how much linked sliders follow one another during editing.
- `EQ Amount` controls how strongly the resulting EQ curve is applied.

The distinction is stated directly under the controls.

## 15. Source identification onboarding

Current source identification depends on optional MediaSession evidence plus later PCM proof. v0.7 makes that dependency visible.

Add a source-detection status area:

- Notification/MediaSession access state;
- active source candidates;
- candidate package/UID when known;
- PCM targeted/mixed status;
- final confidence.

If Notification Access is not granted/connected, show a user action such as `Разрешить определение источника` that opens the appropriate Android settings screen.

Expected path for a normal music app:

1. MediaSession evidence identifies a candidate package/UID at `LIKELY`.
2. next precise capture may request targeted UID capture where Android permits it;
3. valid targeted PCM corroboration can promote to `EXACT`;
4. otherwise the engine remains truthful `MIXED/UNKNOWN` and continues global-safe behavior.

Source-specific behavior must never be enabled merely because an app is foreground or because its label matches a guess.

## 16. DSP truth model

Do not conflate three facts:

1. PCM analysis is available.
2. Android `Equalizer` object exists/is enabled.
3. a DSP transport is verified to affect the intended third-party playback path.

Expose separate runtime/UI fields:

- `Analysis: PCM exact/mixed/...`
- `EQ: active/inactive/unavailable`
- `Verified DSP transport: source/global/unavailable`

`OptionalDspController` may remain fail-closed until a real verification mechanism exists.

`EqController` successfully creating/enabling an Equalizer may justify `EQ active`, but not `DspTransportCapability.VERIFIED_*` without evidence that the current intended output path is actually affected.

## 17. Logs v0.7 durable session index

The logging writer already knows every successfully created URI. v0.7 records that fact instead of relying solely on later discovery.

Introduce a small durable log index, e.g. `LogSessionIndex`, storing:

- session id;
- part URI;
- display name;
- created/modified time;
- location kind (`DEFAULT_MEDIASTORE` or `SAF_TREE`);
- optional byte count when known.

### On log creation

After a part is successfully created, register it in the index.

### On Sessions screen

Build logical sessions from:

1. indexed known parts;
2. MediaStore/SAF discovery results;
3. reconciliation that removes inaccessible stale entries only after an actual failed access/read, not merely because a discovery query was empty.

### Share/open

- `Поделиться последней сессией` uses the indexed logical session when possible;
- rotated parts are still merged into one cache file for share/open;
- an empty MediaStore query must not erase a valid indexed session;
- `Открыть папку` remains best-effort because Samsung's available handlers are outside app control;
- if direct folder opening has no handler, show a clear fallback action rather than implying the logs do not exist.

The in-app Sessions screen must be fully usable without Samsung My Files supporting a particular folder URI intent.

## 18. Runtime telemetry required for the next device test

Every published RuntimeState/log decision should make these values inspectable:

- configured Maximum;
- Safety ceiling;
- user envelope ceiling;
- current Media index;
- recoverable automatic reference/index;
- automatic attenuation dB/index debt;
- configured Target;
- effective Target after manual threshold offset;
- controller action: HOLD/DOWN/RECOVER_UP/HARD_CAP;
- controller reason;
- source candidate package/UID;
- source confidence;
- PCM targeted/mixed state;
- EQ state;
- verified DSP transport state;
- measurement age;
- control latency/write-ack latency.

Black-box event names must distinguish user intent from automatic recovery, e.g. `user_envelope_down`, `user_envelope_up`, `normalizer_down`, `normalizer_recover`, `hard_cap`.

## 19. Route changes and ambiguous state

On output route change:

- reset transient warmup/baseline;
- reset or conservatively rebase recoverable automatic attenuation;
- reload the appropriate device/calibration profile;
- never carry an upward allowance from one output route to another without current user-position evidence.

On ambiguous write provenance:

- pause automatic upward recovery;
- preserve hard-cap/downward safety;
- resume recovery only after the current Media state and envelope can be reconciled.

## 20. Safety and fallback behavior

### Precise PCM available

Use the full adaptive-envelope normalizer and peak/transient protection with the best available source confidence.

### Mixed PCM only

Global adaptive normalization may operate inside the user envelope. `RECOVER_UP` is allowed only to repay attenuation that is unambiguously attributable to SoundCeiling in the current reconciled runtime/route state; quiet content by itself never grants upward authority. App-specific rules requiring exact source identity remain disabled.

### PCM unavailable/blocked

No invented LUFS/dB values. Keep hard cap and any existing safe output-mix fallback that is actually supported. Automatic recovery based on unavailable measurements is blocked.

### DSP unavailable

Does not disable stream-level limiter/normalizer.

### Source unknown

Does not disable safe global Media control. It does disable source-specific claims/policies. Any global recovery remains limited to proven repayment of SoundCeiling's own prior attenuation.

## 21. Explicit non-goals for v0.7

- root/Shizuku requirement;
- changing Samsung's physical system-slider range;
- universal sample-perfect brickwall limiting of all third-party output;
- microphone/call capture;
- claiming actual dB SPL without calibration;
- claiming DSP verification from Equalizer construction alone;
- forcing Samsung My Files to register for an unsupported folder intent;
- replacing another app's playback with a custom AudioTrack pipeline.

## 22. Migration from v0.6

Persisted user settings must be preserved where their meaning remains valid:

- Target, tolerance, strength;
- Minimum/Maximum/Safety Lock;
- peak/transient thresholds;
- EQ band levels, enabled state and Link Strength;
- calibration/device profiles;
- app policies;
- saved control profiles.

Legacy upward fields already persisted by older versions may be reactivated only after normalization/clamping through the v0.7 constraints. If missing or invalid, use v0.7 safe defaults.

The old global one-way wording must be removed from current UI/help/README but historical release docs may remain clearly historical.

## 23. Required tests before release

### Pure controller tests

- app auto-down then quiet content -> gradual recovery up to pre-auto-down reference;
- manual down during recovery -> recovery immediately stops at new user ceiling;
- manual down then loud/quiet material -> never auto-exceeds manual ceiling;
- manual up -> envelope widens and recovery becomes possible up to the new user-selected ceiling;
- Safety Lock/configured Maximum always wins;
- ambiguous provenance blocks recovery;
- Minimum does not cause fighting against a user who deliberately moves below it;
- quiet material with no prior automatic attenuation never causes automatic UP.

### Transient tests

- silence -> normal music onset does not create immediate multi-step emergency;
- absolute dangerous peak can still trigger immediate protection;
- persistent transient can apply additional downward steps over multiple decisions;
- transient attenuation later recovers smoothly if user envelope permits it.

### Source tests

- no Notification Access -> explicit degraded status;
- MediaSession candidate -> `LIKELY`, never `EXACT` by itself;
- targeted PCM corroboration -> `EXACT`;
- unknown/mixed source never enables source-specific rules;
- mixed/unknown global recovery cannot exceed proven prior app attenuation.

### Logs tests

- successfully created part appears in indexed Sessions even if discovery returns empty;
- rotated parts merge into one share file;
- stale indexed URI is pruned only after failed access;
- switching custom/default locations does not lose historical readable sessions unexpectedly.

### UI/source invariants

- no `только вниз` normalization wording in current v0.7 surfaces;
- slider labels may wrap without fixed-height clipping;
- FrequencyMeterView has no hard-coded theme-specific RGB/LTGRAY colors;
- Minimum displays percentage as well as index;
- EQ page contains live spectrum, EQ Amount and correction-curve visualization;
- Link Strength and EQ Amount are distinct controls;
- source onboarding exposes access state/action;
- runtime diagnostics expose user envelope and recovery reason.

### Android integration

- full pure/source/UI regression suite;
- `assembleDebug`;
- installable APK artifact + checksum;
- manual Samsung test using at least music playback and repeated hardware/software volume-key changes.

## 24. Release success criteria

v0.7 is not complete merely because CI is green. On-device behavior must satisfy all of the following:

1. A SoundCeiling automatic reduction can recover smoothly when the material becomes quieter.
2. A manual Samsung Media reduction is never automatically undone beyond the user's new ceiling.
3. A later manual Samsung Media increase widens that ceiling and allows smooth recovery again.
4. Hard Maximum/Safety Lock continues to snap back values above the configured ceiling with no feedback loop.
5. Normal playback onset no longer routinely causes catastrophic transient drops.
6. Volume changes are audibly smoother and ordinary normalization does not make unexplained multi-step cliffs.
7. Source detection shows why it is unknown and provides an explicit route to grant optional source-detection access.
8. DSP/EQ/PCM statuses no longer contradict one another.
9. Logs created successfully are visible/shareable from the app even when Samsung folder-opening/discovery behavior is limited.
10. Light-theme meters and labels are readable and visually coherent.
11. EQ exposes both live frequency information and a meaningful global amount control.
12. No text/glyph clipping remains in Main/Advanced slider rows at the tested device font/display scale.

## 25. Implementation boundary

This design intentionally requires an architectural controller change rather than patching individual symptoms into `NormalizerService`.

The next implementation plan should split work into independent checkpoints:

1. regression fixtures/tests from the two v0.6 device logs;
2. adaptive envelope + provenance model;
3. bidirectional controller/recovery;
4. Transient Guard 2.0;
5. runtime telemetry and control-scale UI;
6. source-detection onboarding/confidence;
7. theme/text-layout fixes;
8. EQ spectrum/curve/amount;
9. durable Logs index and folder/share UX;
10. migration, release gates, Android build and device-test APK.

Each checkpoint must remain buildable/testable, and no release merge may occur until the on-device behavior contract in section 24 is tested.
