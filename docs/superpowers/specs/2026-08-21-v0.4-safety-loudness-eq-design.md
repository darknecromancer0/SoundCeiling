# SoundCeiling v0.4 — Safety, Loudness, EQ and Diagnostics Design

## Status
Approved in chat on 2026-08-21 for implementation after written-spec review.

## Goal
Make SoundCeiling feel immediate, predictable and safe while keeping Simple mode easy. The app must distinguish source loudness from Samsung Media volume, react to dangerous peaks as early as Android permits, preserve the user's manual intent, expose richer controls in Advanced mode, add profiles/presets, improve calibration and diagnostics, and provide an optional EQ/multiband dynamics page without making the main protection path depend on it.

## Core principles
1. **Human volume changes outrank automation.** A user-initiated volume decrease must never be immediately undone by normalization.
2. **No automatic path may exceed a hard safety bound.** Every volume increase request is clamped by the same final guard.
3. **Peak protection and normalization are separate.** Peak protection uses the fastest available signal path; normalization may be slower and smoother.
4. **Do not pretend different loudness units are interchangeable.** Media index, dBFS, LUFS-like loudness and calibrated dB SPL are shown separately.
5. **Simple mode stays simple; Advanced exposes the machinery.** Every Advanced control starts from a documented default and has inline help.
6. **Diagnostics are automatic but bounded.** Logs rotate, old data is deleted, anomalies are detected locally, and nothing is uploaded automatically.

## Android constraints and capability model
The primary measurement backend remains AudioPlaybackCapture because it provides PCM from other apps on Android 10+ when their playback is capturable. Android requires RECORD_AUDIO plus MediaProjection approval for this path. It also only captures usages/apps allowed by Android capture policy.

Global AudioEffect insertion on output-mix session 0 is deprecated by Android for insert effects such as Equalizer. DynamicsProcessing is powerful when it can be attached to an audio session, but SoundCeiling does not own the audio sessions of arbitrary third-party players. Therefore v0.4 must treat global EQ/DSP as an optional capability discovered at runtime, not as the guaranteed safety path.

The app should attempt the following capability tiers and expose the active tier in Diagnostics:
- **Tier A: session/global DSP available and verified** — optional DSP limiter/EQ can be enabled.
- **Tier B: PCM capture + fast Media guard** — default reliable path.
- **Tier C: Media-only guard** — degraded fallback when PCM cannot be captured.

The UI must never claim "zero latency" unless the verified DSP path is actually inserted before the affected output. For PCM-capture fallback, wording is "fastest available protection".

## Loudness model shown to the user
SoundCeiling uses four distinct concepts:

### 1. Samsung Media volume
The system media stream index, for example 0–15 on SM-A528B. This is a control value, not the loudness of the content.

UI examples:
- `Media: 3/15`
- `Media range: 1–5/15`
- `Safety Lock: max 5/15`

### 2. Source peak in dBFS
Instant digital peak of captured PCM. 0 dBFS is the digital full-scale ceiling. Used by the emergency peak detector.

UI example: `Source peak: -1.8 dBFS`.

### 3. Source loudness
A perceptual/averaged loudness estimate used for normalization. v0.4 should add a lightweight LUFS-style/K-weighted short-term loudness meter if practical without a heavy dependency; until validated it must be labelled `Loudness` or `LUFS-like`, not certified ITU BS.1770 LUFS. Existing RMS remains available in Advanced diagnostics.

UI example: `Source loudness: -17.4 LUFS-like`.

### 4. Estimated or calibrated dB SPL
Physical acoustic sound pressure level. This is only presented as meaningful after per-output calibration. Without calibration, the UI shows `SPL: not calibrated` rather than inventing a value.

## Safety architecture
All automatic changes pass through one final decision pipeline:

`measurement -> peak guard / normalizer -> requested index -> user range -> manual override envelope -> Safety Lock -> hard platform clamp -> VolumeApplier`

No class except the approved low-level volume applier and tone/test controller may call `setStreamVolume`.

### Safety Lock
A user-configurable optional hard maximum. It is independent of the normal app maximum.

Semantics:
- If enabled at 5/15, neither SoundCeiling nor a manual volume-up button should leave Media above 5/15 for more than the shortest observable control interval.
- If the user attempts to go above it, SoundCeiling immediately clamps back to the lock and records `safety_lock_clamp`.
- The app cannot literally prevent Android from momentarily receiving a hardware-key press before it observes the new stream value, so the UI must describe this honestly as an enforced clamp rather than OS-level key disabling.
- Safety Lock defaults **off** so upgrading users are not surprised.
- The normal `Maximum Media` must never exceed Safety Lock when the latter is enabled.

### Manual Safety Pause
User volume changes are classified separately from app changes. The app records the exact index it last wrote plus a short acknowledgement window so it can distinguish its own write from a hardware-key or system-slider change.

If the user manually lowers Media:
- effective maximum immediately becomes no higher than the new user-selected index;
- automatic raising is suspended;
- the configured saved min/max values remain unchanged;
- safety lowering remains allowed.

If the user manually reaches mute/minimum:
- enter `MANUAL_SAFETY_PAUSE`;
- normalization may not raise volume;
- peak/safety logic may only hold or lower;
- diagnostics explicitly shows `Paused by user volume`.

When the user manually raises Media again:
- leave pause;
- restore the automation envelope gradually, one permitted index step at a time;
- never exceed configured Maximum Media or Safety Lock;
- a new loud peak can immediately shrink the envelope again.

A one-step manual change must always be recognized. This fixes the prior behaviour where a single step could be effectively swallowed by the controller's rate limiting.

### Emergency Quiet action
A prominent `Quiet now` action exists in Simple mode, Advanced mode and the foreground notification.

Default behaviour:
- reduce Media to the configured Simple/Advanced minimum, or to 1 if the configured minimum is higher than the emergency setting;
- enter Manual Safety Pause;
- temporarily reduce the effective maximum to the emergency index;
- require a manual user volume-up action to begin gradual restoration.

Advanced allows choosing the emergency target index.

### Fail-safe invariants
The following must be unit-tested:
- requestedIndex <= effectiveMax <= configuredMax <= SafetyLock when lock is enabled;
- a user decrease can never be followed by an automatic increase before explicit recovery criteria;
- an app-originated write cannot be mistaken for a user override;
- Safety Lock is applied after normalization, SPL mode, profiles, EQ state and presets;
- missing/invalid measurement data cannot produce an upward jump;
- exceptions in optional DSP/EQ disable that subsystem and preserve the Media guard.

## Fast peak protection
The v0.3 RMS smoothing (~250 ms) must no longer gate emergency protection.

### Raw peak path
For every captured PCM block:
- compute raw block peak immediately;
- evaluate emergency source-peak threshold before slow RMS/LUFS smoothing;
- if the projected output would exceed the configured peak safety threshold, request the required lower Media index in the same cycle;
- emergency decreases ignore normal decrease rate limiting;
- upward restoration remains rate-limited.

Target for Tier B on a typical 48 kHz capture stream: react on the first or next available capture block, normally tens of milliseconds rather than hundreds. Actual end-to-end latency is recorded in diagnostics where measurable.

### Optional DSP limiter
On devices where DynamicsProcessing or another verified audio effect can be attached to the relevant path, offer `DSP peak limiter (experimental)` with capability status. It must never be silently assumed to work. A startup self-test must confirm that the effect object is enabled/controllable; if not, fall back to the Media guard and mark a yellow diagnostic warning.

## Normalization
Normalization remains optional and is independent from peak safety.

Presets:
- **Off** — no automatic upward normalization; peak guard still works.
- **Light** — gentle correction, larger loudness tolerance, slow upward release.
- **Medium** — default balanced correction.
- **Strict** — narrow loudness window, stronger correction, still bounded by all safety rules.
- **Custom** — exposes exact parameters.

Advanced custom controls:
- target loudness;
- loudness tolerance/deadband;
- normalization strength;
- downward attack;
- upward release;
- hold after a loud event;
- max downward Media steps per control action;
- max upward Media steps per control action;
- peak emergency threshold;
- minimum Media;
- maximum Media;
- emergency Quiet target;
- Safety Lock enable/value;
- auto-mute permission;
- calibrated SPL target/ceiling where available.

All controls have a small `?` button beside the label. Pressing it opens a short explanation containing: what the control changes, the default, a safe experimentation range, and the side effect of increasing/decreasing it.

## Default values and reset behaviour
Every Advanced control must have a stable code-defined default. UI sliders initialise to the saved value; on first run this is exactly the default. A `Reset to defaults` button restores all Advanced parameters for the active settings profile.

Proposed defaults for implementation/testing:
- normalization preset: Medium;
- target loudness: current v0.3 comfort-equivalent target, translated to the new loudness scale during implementation validation;
- source peak emergency threshold: -2 dBFS;
- minimum Media: 1 index;
- maximum Media: 70% of stream max;
- Safety Lock: off;
- Quiet now target: 1 index;
- manual recovery: gradual, 1 index per release interval;
- auto mute: off;
- DSP limiter: auto/experimental, only when verified;
- theme: System.

Exact numeric attack/release/loudness defaults are implementation-plan constants and must be backed by tests and labelled in the help text. They should favour fast downward protection and conservative upward restoration.

## Settings profiles and presets
Two concepts are distinct:

### Built-in presets
Read-only templates supplied by the app:
- **Safe / conservative** — low max, strict peak guard, slow recovery.
- **Balanced** — recommended default.
- **Stable loudness** — stronger normalization and narrower tolerance.
- **Movie / dynamic** — light normalization, keeps more dynamics, strong peak guard.
- **Speech** — stronger mid-focused normalization when multiband support is available; otherwise normal loudness normalization.

Applying a preset copies its values into the active editable settings profile. The user can then change individual sliders without modifying the built-in template.

### User profiles
The user can:
- save current settings as a named profile;
- duplicate a profile;
- rename it;
- delete it;
- switch profiles;
- restore a profile to its saved snapshot;
- see whether current controls differ from the saved profile (`Modified`).

Profiles include Simple/Advanced range, safety, normalization and EQ parameters, but calibration data remains keyed to the physical audio output and is not duplicated into arbitrary profiles.

## Simple mode
Simple mode contains only the controls a normal user should need:
- Comfort / target loudness;
- Minimum Media;
- Maximum Media;
- normalization Off/Light/Medium/Strict;
- `Quiet now`;
- Start/Stop;
- concise status card.

If Safety Lock is active, Simple mode shows a small lock badge and the hard maximum, but detailed configuration stays in Advanced.

Simple mode must not expose raw attack/release or technical threshold sliders.

## Advanced mode
Advanced becomes the complete control surface. Sections:
1. **Volume range** — min, max, emergency target, Safety Lock.
2. **Peak protection** — source peak threshold, emergency behaviour, DSP capability/status.
3. **Normalization** — preset, target loudness, tolerance, strength, attack/release/hold and step sizes.
4. **SPL** — calibrated target/ceiling, current output profile and calibration state.
5. **Behaviour** — auto mute, user override recovery, startup behaviour.
6. **Live meters** — Media index, source peak dBFS, RMS, loudness/LUFS-like, estimated/calibrated SPL.
7. **Existing five-band visualizer** — retained as a read-only live visualization.
8. **Profile controls** — load/save/reset.

Every slider row includes a compact help button.

## EQ and frequency-dependent dynamics
Add a separate `EQ` destination. Keep the existing five-band visualizer in Advanced and also show it on the EQ page.

### EQ controls
Prefer a device-reported number of bands when using Android Equalizer. If a reliable global effect is unavailable, show EQ as unsupported for global playback rather than pretending values are active.

Provide:
- enable/disable;
- reset flat;
- built-in presets;
- per-band gain controls;
- active/inactive capability status.

### Per-band normalization / dynamics
Where DynamicsProcessing is available on the relevant audio path, allow per-band behaviour:
- `EQ only`;
- `Light normalize`;
- `Medium normalize`;
- `Strict normalize`.

This is explicitly optional. If global third-party playback cannot be processed by the device/API, the controls are disabled with an explanation while the analyzer continues to work.

## Calibration redesign
Calibration becomes a guided wizard.

1. Detect and show current output device.
2. Explain that Media index and SPL are different.
3. Select a fixed calibration Media index and lock it for the tone.
4. Play a safe known test tone after stopping normalization.
5. Ask for **the value measured by an external SPL meter**, not a value chosen by feel.
6. Save calibration against the output-device key.

Also provide `I do not have an SPL meter`:
- exits/continues in dBFS/loudness mode;
- SPL UI remains clearly uncalibrated;
- no fabricated physical dB number.

For headphones, warn that a phone microphone near the earcup is only a rough estimate; accurate SPL requires a suitable coupler/measurement setup.

## Diagnostics and local anomaly detection
Add a `Diagnostics` destination with three severity classes:
- **Green** — known-good state: capture active, signal present, safety guard active, log writable, route stable, measurement backend healthy.
- **Yellow** — degraded but usable: optional DSP unavailable, no SPL calibration, capture policy excludes some audio, elevated latency, repeated rate limiting, EQ unsupported.
- **Red** — definite or safety-relevant fault: attempted command above Safety Lock, unexpected mute, user override ignored, capture failure, write failed, rapid oscillation, illegal volume jump, protection reaction missed beyond threshold.

Each item contains a short human-readable explanation and, when appropriate, a suggested action.

### Automatic anomaly rules
At minimum detect:
- `safety_cap_violation_attempt`;
- `manual_override_ignored`;
- `unexpected_auto_raise`;
- `unexpected_zero`;
- `volume_oscillation`;
- `peak_reaction_slow`;
- `capture_stalled`;
- `projection_lost`;
- `optional_dsp_failed`;
- `log_write_failed`.

Diagnostics may automatically mark problems but never automatically upload logs.

## Logging policy
Replace continuous verbose disk flushing with a bounded black-box model.

- Keep compact session events on disk.
- Keep high-frequency decision trace in an in-memory ring buffer.
- When an anomaly occurs, persist a window containing context before and after the event.
- Rotate individual files.
- Enforce a total retained-log budget, default 16 MiB.
- Delete oldest sessions automatically when over budget.
- Provide `Export diagnostics` and `Clear logs` actions.
- Show current disk usage in Diagnostics.

No network transmission is added.

## Theme and icon
Appearance settings:
- System default;
- Dark;
- Light.

Persist theme per app, not per audio settings profile.

Add a simple adaptive launcher icon concept: speaker + horizontal ceiling/limit line above a waveform. It must remain readable at small launcher sizes and have monochrome support where Android launchers use themed icons.

## Navigation
Drawer/destination set for v0.4:
- Simple
- Advanced
- EQ
- Calibration
- Diagnostics
- Appearance

## Migration from v0.3
- Preserve existing target/max/normalization/SPL calibration where mappings are unambiguous.
- New min Media defaults to 1.
- Safety Lock defaults off.
- Existing speed preset maps into new attack/release defaults.
- Existing logs remain untouched; new retention logic manages only v0.4-managed log files unless safe migration is implemented.

## Testing strategy
### Pure unit tests
- safety pipeline and invariants;
- manual user change classification;
- one-step up/down detection;
- Manual Safety Pause and gradual recovery;
- Safety Lock clamp;
- emergency Quiet behaviour;
- raw peak path independent of RMS smoothing;
- normalization presets and custom settings;
- profile serialization/migration;
- diagnostics severity and anomaly rules;
- log retention/ring buffer policy;
- loudness meter math.

### Android/source contract tests
- only approved classes write system volume;
- all Advanced controls have defaults/help metadata;
- Simple exposes min/max and normalization level;
- navigation includes EQ/Diagnostics/Appearance;
- theme and profile persistence keys exist;
- capture and optional DSP failures fall back safely.

### CI build gates
- pure Java tests with warnings as errors;
- source invariants;
- Android assembleDebug;
- artifact checksum;
- APK upload.

### Device test checklist for SM-A528B
- one-step manual volume down is respected;
- one-step manual volume up starts gradual recovery rather than a jump;
- mute/minimum enters pause and does not auto-raise;
- Safety Lock clamps manual attempts above the lock;
- sudden loud source triggers first-block/near-first-block lowering in Tier B;
- normal quiet/loud content converges without oscillation;
- calibration wizard is understandable without prior explanation;
- Diagnostics reports active backend and any degraded capabilities;
- logs stay below configured budget over extended use.

## Acceptance criteria
v0.4 is ready for merge only if:
1. no automatic code path can exceed the final effective safety maximum;
2. a manual user decrease is never silently undone;
3. emergency peak detection no longer depends on the 250 ms RMS smoother;
4. Simple has min/max and normalization strength choices;
5. Advanced restores/expands controls, all with defaults and inline help;
6. settings profiles and built-in presets work;
7. calibration explicitly explains what SPL value to enter;
8. Diagnostics produces green/yellow/red statuses and detects defined anomalies;
9. logs are automatically bounded and old logs are removed;
10. EQ/multiband features degrade honestly when global processing is unavailable;
11. dark/light/system themes and the new adaptive icon are present;
12. CI is green and an APK artifact is verified before merge.

## Non-goals
- Claiming certified medical/hearing protection.
- Claiming exact dB SPL without calibration.
- Claiming true pre-output zero-latency limiting when Android only gives a captured copy of third-party playback.
- Routing all third-party media through a custom virtual audio device in v0.4.
- Uploading telemetry or logs automatically.
